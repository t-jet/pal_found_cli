# Scope and preconditions
Admin and Filesystem CLI generic error classification for BUG-027 in current Windows worktree. Use isolated SDK-shaped async iterator doubles and installed foundry_sdk PermissionDeniedError; no credentials or network. Capture stdout error envelope and main process return.

# Given/When/Then scenarios
1. Given an async iterator without SDK `_page_iterator`, when a paginated Admin or Filesystem command runs, then no items are emitted and stdout envelope exit_code equals returned exit code.
2. Given SDK PermissionDeniedError after guard success, when either command runs, then envelope and process both use exit 3.
3. Given AccessControlGuard denial, when either command runs, then envelope and process use exit 8 and SDK is not called.
4. Given SDK server error, when either command runs, then envelope and process use exit 6.

# Edge and negative checks
Exercise empty iterator and one-item iterator without page interface; both must fail before partial output. Invalid input TypeError classification should remain deliberate and consistent.

# Expected outputs and test data
Exact JSON `exit_code` values 1, 3, 6, or 8 as applicable, matching process return. No pagination metadata on failure. Mock resources: Admin user list and Filesystem folder children. Use current client config with access guard patched only for the target branch. No write side effects.

# Approval gate
Tech Lead or Architect approval required before execution under QA standard. Ontology design approval in TASK-006 does not cover Admin/Filesystem.
