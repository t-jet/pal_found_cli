### Key technical facts
- Covers media item upload, download, metadata retrieval, and transformation (thumbnail) workflows.
- Binary downloads: get_result, read, read_original, retrieve all return bytes (response_type=bytes) -> BinaryDownloadHandler required via with_streaming_response (confirmed in story description).
- Binary uploads: upload and upload_media accept bytes body (bounded file read before client construction).
- FR-ATTR-4 explicitly lists media_sets.media_set.* -> include_attribution=True (unlike most other namespaces). transform and upload_media carry an Attribution header param.
- No ResourceIterator in this namespace -> PaginationHelper not required.
- Metadata-only allow-list (5 PERMITTED): media_set.get, media_set.get_rid_by_path, media_set.get_status, media_set.info, media_set.metadata.
- Write set (14) for ACL: abort, calculate, clear, commit, create, get_result (content read of transformation result -> treated as content read, blocked in metadata-only), register, transform, upload, upload_media. NOTE: content reads read/read_original/retrieve/get_result are semantic reads (consume data, no mutation) but are BLOCKED in metadata-only because they expose file content.
