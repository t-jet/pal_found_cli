## Analysis stage: technical scope, constraints, and dependencies

### Technical scope
- Implement the foundry-media-sets Claude skill and CLI exposing exactly 19 SDK v2 media_sets operations (single MediaSet client path).
- CLI names kebab-case; OP_SPECS keys/ACL paths snake_case; immutable operation catalog.
- Nested client dispatch: client.media_sets.MediaSet.
- Binary downloads: read, read_original, retrieve, get_result return bytes -> BinaryDownloadHandler via with_streaming_response (bounded to FR-DL limits, JSON envelope on stdout).
- Binary uploads: upload and upload_media accept bytes body -> bounded file read (--file) before client construction.
- No pagination (no ResourceIterator) -> PaginationHelper not required.
- Shared options: --timeout, --format, --pretty.

### Constraints
- FR-ATTR-4 includes media_sets.media_set.* -> include_attribution=True (transform and upload_media carry Attribution headers). Attribute RIDs from FOUNDRY_AGENTIC_CLI_ATTRIBUTION_RIDS when enabled.
- Metadata-only allow-list packaged per namespace: 5 PERMITTED / 14 BLOCKED (match canonical). Permitted: get, get_rid_by_path, get_status, info, metadata.
- ACL write set (9): abort, calculate, clear, commit, create, register, transform, upload, upload_media. Content reads (read/read_original/retrieve/get_result) are semantic reads but expose file content -> blocked in metadata-only.
- Transactional media-set lifecycle: create (open transaction) -> upload -> commit / abort. CLI must pass --transaction-id when the media set is transactional.
- B3-only tracing via invocation_scope; SDK-native error handling; exit codes per ADR-001.
