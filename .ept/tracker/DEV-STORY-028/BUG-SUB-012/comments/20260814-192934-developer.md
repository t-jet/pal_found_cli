## Root cause

.github/workflows/publish.yml conda job upload step (line 85) uses the file glob conda-channel/*/*.tar.bz2. conda-build 26.7.0 (installed into base per QUESTION-118 answer, 2026-08-14) produces only .conda artifacts under the noarch subdir, e.g. .ept/tmp/conda-channel/noarch/pal_found_cli-0.1.0-py_0.conda (80499 bytes, HEAD 5746815). The .tar.bz2 glob matches zero files, so the token-present branch of the upload can never publish the package (TESTEXEC-028 COND-TC-012 FAIL).

## Reproduction

- Glob simulation: Get-ChildItem -Recurse .ept/tmp/conda-channel -File | Where-Object { $_.Name -like '*.tar.bz2' } -> 0 matches
- Same filter with '*.conda' -> 1 match (pal_found_cli-0.1.0-py_0.conda)

## Fix plan

1. publish.yml: change the conda upload glob from conda-channel/*/*.tar.bz2 to conda-channel/*/*.conda (upload step, line 85).
2. tests/test_release_artifacts.py: add a regression assertion that the publish.yml conda upload glob targets the *.conda artifact format.
3. Verify: YAML parse of publish.yml; glob simulation against the real built artifact (0 tar.bz2 / 1 conda); run pytest tests/test_release_artifacts.py (exit 0).
