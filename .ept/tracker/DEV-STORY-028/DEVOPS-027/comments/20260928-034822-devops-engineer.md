### Diagnosis (from publish run 36363162512, same run as DEVOPS-026)
- conda job "Build conda package" failed with:
  `conda: error: argument COMMAND: invalid choice: 'build' (choose from activate, check, clean, ...)`
- The workflow step does `conda install --yes conda-build` then `conda build conda.recipe --output-folder conda-channel`.
- Root cause: `conda build` subcommand is not registered in the activated `release` environment (setup-miniconda with auto-activate-base: false). The conda-build plugin/subcommand is not exposed as a `conda build` subcommand on this conda version, OR conda-build was installed into base but the non-base activated env doesn't see it.
- This is a WORKFLOW BUG fixable in publish.yml, within DevOps scope.

### Fix approach (fix in publish.yml in pal_found_cli_tool)
- Robust way to invoke conda-build: activate base before building, or call the `conda-build` binary directly (it is installed as a standalone command), or use `conda install conda-build --channel conda-forge` into the SAME env being used.
- Decide final approach after local reproduction if possible; otherwise apply best-known robust form:
  `conda install --yes --channel conda-forge conda-build conda-verify`
  then build with the standalone `conda-build` binary, or ensure base env is used.
- Also enable upload to channel `t-jet` via `anaconda upload --user "$ANACONDA_USERNAME"` using ANACONDA_API_TOKEN secret.
