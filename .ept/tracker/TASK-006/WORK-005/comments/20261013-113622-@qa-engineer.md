# Scope
Review all 51 frozen operations: Streams 15, Media Sets 19, Third Party Applications 9, Widgets 8. Compare each distributed record against exact CLI OP_SPECS, parser, runtime path, and local SDK method/model. Record one hashed decision per operation in four namespace review JSON files.

# Preconditions and data
Use current local skills/tool revisions and pinned SDK source. No live credentials required. Use example shell RIDs, JSON payloads, small binary files, fake page responses, and denied/missing/invalid response fixtures where executable probes are needed. Do not mutate production data.

# Scenarios
For each operation: Given frozen key and source, when matching record and CLI invocation are compared, then method, required/optional inputs, effect, result shape, and error meaning agree with SDK and parser; example selects intended operation. For read and write paths, check policy classification and observable effect separately. For list paths, check page size/token/all/max-pages, first/next page shape, and continuation. For uploads/downloads, check file bound, output filename, byte/metadata result, and truncation. For asynchronous jobs, distinguish accepted state from final outcome.

# Edges and negative cases
Check empty pages with continuation, server short/long pages, absent optional selectors, conflicting selectors, 16 MiB boundary, invalid JSON, missing required args, denied access, missing resources, timeout/network failure, and state conflicts where relevant. Compare stated exit codes with taxonomy (1 input, 3 permission, 4 missing, 8 policy); SDK/server errors need accurate explanation.

# Expected outputs and reporting
Each of 51 rows gets pass or fail with record/CLI/SDK SHA-256, source-backed note, and defect ID for fail. A discrepancy needs reproducer with command/fixture, expected versus actual, version/commit, severity, and TASK-006 link. Summary gives exact pass/fail/pending counts. No QA sign-off while High defects or unreviewed rows remain.
