# Scope
Independent QA for BUG-011 (16 paginated Ontology operations), BUG-013 (typed object primary key), and BUG-017 (plain string attribution). Candidate is current local worktree at tool HEAD bfdee738 and skills HEAD 419b261 with uncommitted fixes.

# Preconditions and test data
Use installed local foundry_sdk shape, isolated AsyncResourceIterator and page-envelope doubles, no Foundry credentials or network. Use tokens start/second/third, page size 2, batch pages 2, item IDs 1-5, typed key {"employeeId":{"type":"stringValue","value":"50030"}}, and attribution my-app. Keep mock configuration separate from source under test.

# Given/When/Then scenarios
1. Given each of 16 operations and two SDK pages, when CLI paginates, then stdout contains all ordered item records, second call receives continuation, and stderr reports actual pages/items/cursor.
2. Given empty page with cursor followed by oversized page, when CLI fetches two pages, then no item is dropped, two pages are counted, and resume cursor is correct.
3. Given final page without cursor, when batch limit exceeds available pages, then CLI stops after one fetch and omits continuation.
4. Given public AsyncResourceIterator with no raw client, when CLI fetches a batch, then it consumes one complete SDK page per fetch, including short and oversized pages.
5. Given valid typed primary-key JSON, when get-edits-history runs, then SDK receives mapping; malformed JSON returns user-input exit 1 and SDK is not called.
6. Given scalar attribution and valid parameters JSON, when query execute runs, then SDK receives attribution as string and parameters as mapping; malformed parameters returns exit 1.
7. Given copied offline Ontology skill, when novice reader follows operation records, then key shape, attribution type, pagination results and cursor guidance match executable behavior.

# Edge and negative checks
Include empty result, short page, oversized page, page token resume, max batch bound, malformed JSON, unauthorized access (exit 3), and SDK exception propagation. Timeout/network failure checks stay in general CLI gate unless changed by these fixes.

# Expected outputs
Success exit 0; JSON item list on stdout; pagination metadata JSON on stderr. Input parse failure exit 1 with no SDK call. Access-control denial exit 3. Error exit codes and stderr follow project taxonomy. No write side effects.

# Approval gate
Tech Lead or Architect review required before execution under QA standard. Existing TESTCASE-046/047 are skill-content designs and do not cover these runtime fixes.
