Evidence reviewed: installed SDK Session exposes rid but no session_token; SDK TRACE_ID_VAR, SPAN_ID_VAR, and SAMPLED_VAR populate X-B3-* headers; an unknown-length stream cannot reveal exact source size without unbounded draining. Decisions: (1) keep session_token as an optional nullable compatibility field. Session.rid is session_id. Accept session_token when missing, null, or a string; never synthesize it. (2) Use SDK-native B3 propagation only for this story through TRACE_ID_VAR, SPAN_ID_VAR, and SAMPLED_VAR to X-B3 headers. Defer explicit W3C traceparent integration. (3) For unknown Content-Length, read at most limit+1 bytes. Keep source_size nullable; when truncating, report source_size_at_least=limit+1 and emit the warning. Never drain the remaining stream. These choices preserve SDK compatibility, bounded resource use, and deterministic tests.
