### Analysis performed

Reviewed all 25 questions from `open_questions.md` and their answers (A1.1-A6.5) to identify remaining gaps. Additional SDK research and external library/format research was performed:

1. **SDK attribution/tracing research**: Analysed `foundry_sdk/_core/context_and_environment_vars.py` and `foundry_sdk/v2/core/models.py`. Found that `Attribution = str` (a plain RID string or comma-separated list), `ATTRIBUTION_VAR` holds a list of resource RIDs sent as HTTP headers for billing attribution, and `TRACE_ID_VAR`/`SPAN_ID_VAR`/`SAMPLED_VAR` are W3C/B3 distributed tracing context vars. Attribution is used across 4 namespaces (`functions`, `ontologies`, `language_models`, `media_sets`).

2. **TOON format research**: Fetched `github.com/toon-format/toon-python`. Official Python library (`toon_format` package) is **v0.9.0-beta.1** -- beta status, API not yet stable, install only from GitHub (not stable PyPI release). This is a blocking decision point for the output format implementation.

3. **Claude Code Skills format research**: Fetched `code.claude.com/docs/en/skills`. Confirmed exact skill format: `.claude/skills/<skill-name>/SKILL.md` with YAML frontmatter + markdown. Supporting files (scripts, templates) can accompany SKILL.md. Each namespace should be one skill directory.

### Items still open from Round 1

- **Q5.3 (async client)**: Answer said "not sure." A concrete choice (sync only / async internally / both) is required before starting implementation.
