## Status: In Progress — Architecture Deliverables Documented (2026-05-02)

### Architecture Approach Summary

The Foundry CLI Agentic Toolset is architected as a **distributed, stateless, subprocess-invocable CLI system** consisting of 21 Claude Code skills exposing 355 operations from the Palantir Foundry API v2. The design follows an **agentic-first architecture** optimized for AI agent invocation via subprocess calls.

#### Core Architectural Decisions

**1. Distribution Model: File-Copy Deployment**
- No build step, no package installation (beyond pip dependencies)
- Each skill is self-contained (CLI + shared module + SKILL.md)
- Zero daemon processes; fully stateless per invocation
- **Rationale**: Simplifies deployment, version control, and agent platform integration

**2. Shared Common Module Pattern**
- Single source of truth: `_foundry_cli_common.py` (500-800 LOC)
- Copied into each namespace skill's `scripts/` directory
- Contains 11 reusable components (auth, retry, output, access control, etc.)
- **Rationale**: Avoids inter-skill dependencies while maintaining consistency

**3. Layered Security Model**
- **Layer 1**: Authentication (UserTokenAuth from FOUNDRY_TOKEN)
- **Layer 2**: Access Control Guard (8-step precedence evaluation)
- **Layer 3**: SDK API call execution
- Early rejection at each layer; fail-fast on denial
- **Rationale**: OWASP defense-in-depth; minimal attack surface

**4. Dual Output Format Strategy**
- **JSON**: Structured data; always available (stdlib)
- **TOON**: Human-readable tables; auto-selected for uniform arrays
- Algorithm defined in ADR-004
- **Rationale**: Agent-friendly (JSON) + human-friendly (TOON) outputs

**5. Structured Error Handling**
- Exit code taxonomy (ADR-001): 15 distinct error classes
- JSON error envelope on stdout for all failures
- NDJSON logs on stderr (ADR-005)
- **Rationale**: Parseable errors for agent error handling

### Non-Functional Requirements

#### Performance & Scalability

| NFR | Specification | Implementation |
|---|---|---|
| **NFR-PERF-1** | CLI startup < 500ms (cold start) | Lazy SDK client initialization; no network calls on import |
| **NFR-PERF-2** | Pagination batch size: 50-500 (configurable) | `--page-size` argument; default 100 |
| **NFR-PERF-3** | Concurrent operations: up to 10 parallel CLI invocations | Stateless design; OS-level file locking for session files |
| **NFR-SCALE-1** | Max download size: 1.5 MB (configurable) | `MAX_DOWNLOAD_BYTES` env var; truncated flag on exceed |
| **NFR-SCALE-2** | Max response payload: 50 MB | SDK default; no CLI-level override |

#### Reliability & Availability

| NFR | Specification | Implementation |
|---|---|---|
| **NFR-REL-1** | Retry on transient errors (429, 503) | Exponential backoff: 0.5s, 1s, 2s, 4s (4 attempts max) |
| **NFR-REL-2** | Timeout per API call: 30s (configurable) | `asyncio.wait_for()` with `TIMEOUT_S` env var |
| **NFR-REL-3** | Session TTL: 7 days | Auto-cleanup on session operations |
| **NFR-REL-4** | Graceful SIGTERM handling | Cleanup in-progress downloads; close SDK client |

#### Security

| NFR | Specification | Implementation |
|---|---|---|
| **NFR-SEC-1** | Token never logged in plaintext | Only last 4 chars in debug traces |
| **NFR-SEC-2** | Session files owner-read/write only | `chmod 0o600` on Unix platforms |
| **NFR-SEC-3** | Download path validation | `pathlib.Path.resolve()` + prefix check |
| **NFR-SEC-4** | OWASP A05 mitigation | No home-dir `.env` loading (ADR-006) |

#### Platform Support

| NFR | Specification | Implementation |
|---|---|---|
| **NFR-PLAT-1** | Python 3.11.x, 3.12.x support | Tested; 3.13 deferred (tech debt) |
| **NFR-PLAT-2** | Windows 11, macOS, Linux support | `pathlib.Path` for cross-platform paths; platform-specific SIGTERM handlers |
| **NFR-DIST-1** | Zero external dependencies for auth/retry/output | stdlib only for core logic; SDK + toon-python as only external deps |

### Migration Procedure

**Phase 1: Preparation (Week 1)**

1. **Prerequisites Validation**
   - Verify Python 3.11.x or 3.12.x installed on target system
   - Confirm `pip` available
   - Validate network access to Palantir Foundry API v2 endpoint
   - Obtain `FOUNDRY_TOKEN` from Palantir Foundry admin

2. **Repository Setup**
   - Clone target repository (or use existing)
   - Create `.claude/skills/` directory if not exists
   - Add `.foundry-data/` to `.gitignore`

3. **Dependency Installation**
   ```powershell
   # Windows PowerShell
   pip install python-dotenv
   pip install 'toon-python @ git+https://github.com/toon-format/toon-python.git@v0.9'
   # foundry-platform-sdk: use in-repo copy or install separately
   ```

**Phase 2: Core Infrastructure Deployment (Week 2-3)**

1. **Deploy EPIC-001 (DEV-STORY-001 through DEV-STORY-004)**
   - Copy `_foundry_cli_common.py` template to development workspace
   - Implement 11 components (ConfigLoader, AuthProvider, etc.)
   - Unit test each component with pytest
   - Code review and approval

2. **Configuration File Creation**
   - Create `.env` file at repo root
   - Set minimum required variables:
     ```env
     FOUNDRY_HOSTNAME=your-instance.palantirfoundry.com
     FOUNDRY_TOKEN=your-token-here
     FOUNDRY_AGENTIC_CLI_LOG_LEVEL=WARNING
     ```
   - Validate config loading with test script

**Phase 3: High-Priority Skills Rollout (Week 4-7)**

1. **Deploy EPIC-002 (DEV-STORY-005, DEV-STORY-006)**
   - `foundry-datasets` skill: 26 operations
   - `foundry-filesystem` skill: 31 operations
   - Integration test: list datasets, get file content

2. **Deploy EPIC-003 (DEV-STORY-007, DEV-STORY-008)**
   - `foundry-ontologies` skill: 55 operations
   - `foundry-functions` skill: 7 operations
   - Integration test: search ontology objects, execute function

3. **Deploy EPIC-004 & EPIC-005 (DEV-STORY-009 through DEV-STORY-013)**
   - Admin, audit, AI/models skills
   - Integration test: list users, create session, invoke agent

**Phase 4: Remaining Skills Rollout (Week 8-10)**

1. **Deploy EPIC-006 & EPIC-007 (DEV-STORY-014 through DEV-STORY-022)**
   - Data pipeline and remaining namespace skills
   - Integration test suite per namespace

**Phase 5: Knowledge Skill & Finalization (Week 11)**

1. **Deploy EPIC-008 (DEV-STORY-023)**
   - Author `foundry/SKILL.md` knowledge content
   - Validate auto-loading in VS Code skill runner

2. **Final Validation**
   - Run full integration test suite (all 355 operations)
   - Performance test: measure CLI startup time, operation latency
   - Security audit: verify token handling, access control, path validation
   - Documentation review: verify all ADRs, SAD-001, SRS-001 accuracy

**Phase 6: Production Cutover (Week 12)**

1. **Production Deployment**
   - Copy all 21 skills to production `.claude/skills/` directory
   - Set production `.env` configuration
   - Monitor first 48 hours of production usage
   - Address any emergent issues

2. **Post-Deployment**
   - Document lessons learned
   - Update operational runbooks
   - Schedule first quarterly SDK upgrade review
