### Test cases (Given/When/Then)
**TC-046-01 inventory one-to-one (AC-D-013-08).** Given the 28 frozen discovery keys, when record headings are enumerated in the discovery references and per-resource files, then every key has exactly one record and no extra or duplicate record exists.
**TC-046-02 record completeness sample (AC-D-013-02..05).** Given action_type.get, action_type_full_metadata.get, linked_object.get_linked_object, object_type.get_full_metadata, ontology.load_metadata, ontology_object.search, ontology_value_type.get and query_type.list, when each is read, then resource, effect and side effect, input meaning, result and failure interpretation and a coherent example are correct against the installed CLI.
**TC-046-03 offline copied-folder representative run (AC-D-013-06,07).** Given the copied folder with no network, when a novice agent follows one example per client with mock or recorded output, then it chooses valid inputs, interprets the result and next operation, and every required local link resolves.
**TC-046-04 install prerequisite (BR-012-09).** Given pal-found-ontologies/SKILL.md, when the install block is read, then it names pal_found_cli and gives conda `-c t-jet`, pip and uv commands.
**TC-046-05 300-line leaf limit (SA-DES-012).** Given every markdown part, when line counts are checked, then each part is at most 300 lines.
**TC-046-06 RID and batch lookups (AC-D-013-03).** Given action_type.get_by_rid, action_type.get_by_rid_batch, object_type.get_by_rid_batch and linked_object.get_linked_object, when each is read, then the RID input form, the batch payload, and the relationship between the two linked-object directions are stated.
**TC-046-07 discovery metadata semantics (AC-D-013-04,05).** Given object_type.get_full_metadata, object_type.get_edits_history and ontology.load_metadata, when the records are read, then the meaning of full metadata, edit history and metadata load, and the empty or pending interpretation, are stated.
**TC-046-NEG-01 missing or duplicate record.** Given a key with no heading or two headings, when the inventory check runs, then it fails naming the key.
**TC-046-NEG-02 unsupported call.** Given an operation not in the register, when the skill is read, then it is not presented as callable.
**TC-046-NEG-03 stale example.** Given an example selecting a different resource.operation than its heading, when parsed, then it fails.
**TC-046-NEG-04 unresolved link.** Given a relative link that escapes the folder or targets a missing file, when resolved, then it fails.
### Expected outputs
28/28 keys with exactly one record; zero duplicates or extras; completeness sample passes; zero unresolved local links; install block present; every part at most 300 lines; RID and metadata semantics documented.
