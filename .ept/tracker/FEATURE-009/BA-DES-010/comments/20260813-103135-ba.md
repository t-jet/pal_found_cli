## Business design plan - BA-DES-010 (author ba)

### Business case
Each CLI skill can be used only when the user knows the exact input formats and allowed parameter variants the tool accepts. The Project Owner requires each specific pal-found-* skill file to fully document all JSON formats and allowed parameter variants for its tool, so the tool is usable without consulting any other source. This makes every namespace skill self-contained.

### Acceptance criteria (scope for design)
- Given a specific CLI skill file, when a user reads it, then it lists every JSON format the tool accepts.
- Given a specific CLI skill file, when a user reads it, then it lists every allowed parameter variant for each operation.
- Given only the skill file, when a user runs the tool, then they can do so correctly without consulting any other source.
- Given the tool and its skill file, when they are compared, then the documented formats and variants match the tool.
- Given any skill file, when its length is checked, then it stays within the composition limit (parts split if needed).

### Deliverables
1. Business design document: .ept/docs/deliverables/business_design/BA-DES-010-business-design.md (logic flow, UI/UX mocks abstract, API specs abstract, data structures in business terms, content structure for formats/variants, migration procedure).
