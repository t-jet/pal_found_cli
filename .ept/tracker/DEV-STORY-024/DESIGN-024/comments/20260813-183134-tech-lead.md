## Concrete technical plan

**Summary:** Repository split with history preservation and submodule/remote rewiring.

**Components:** Migration inventory and content classifier; history-preserving move procedure; .gitmodules/remote updater; fresh-clone consistency check.

**Interfaces:** Inputs: current repository, submodule URLs, final repository names. Outputs: three repositories, updated submodule metadata, migration checklist.

**Integration:** FEATURE-003/EPIC-010; DEV-STORY-025 public hosting; DEV-STORY-027 reference sweep; later PyPI/conda stories consume tool repo.

**Risks:** History loss, content misclassification, stale remotes. Mitigate with pre-move manifest, tagged backup, fresh clones, and rollback to last combined layout.

**Acceptance criteria:**
- Given the source tree, when migration runs, then each path lands in its named repository with history. Given fresh clones, when submodules initialize, then final URLs resolve. Given old layout backup, when rollback is required, then source remains recoverable.

**Test strategy:** Manifest diff, git log/path history, submodule init, fresh clone, content ownership and rollback checks.

**Estimate:** 8 story points; DESIGN 6h, DEV 24h, UNITTEST 12h, CODEREVIEW 6h, TESTCASE 8h, TESTEXEC 8h, DEVOPS 12h.
