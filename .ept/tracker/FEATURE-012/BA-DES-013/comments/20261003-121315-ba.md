## BA design plan and sources (2026-10-03)
Business case: an unfamiliar agent must use installed skills and CLI offline to choose a supported Foundry operation, understand every input and effect, and interpret its result without extra guidance.
1. Read approved BA-ANA-013 and SA-ANA-013, FEATURE-012, EPIC-012, QUESTION-152, and prior FEATURE-008/009/011 design documents. Verify the supported inventory and scope boundary.
2. Define the end-to-end agent flow and the general-skill versus namespace-skill content responsibilities in business terms.
3. Define per-operation content and review records for effect, inputs, side effects, results, failures, examples, and source traceability. Define empty, paged, pending, timeout, and permission cases.
4. Specify offline distribution and migration, including packaged local Markdown parts, without new CLI behavior. Mark UI and new API interface design not applicable.
5. Write one business design deliverable under `.ept/docs/deliverables/business_design/`, trace BR-012-01..11 and AC-012-01..13, and register it in `.ept/docs/document_index.md`.
6. Create sprint-sized Developer Stories under FEATURE-012 and EPIC-012 with Given/When/Then criteria; link and promote them per workflow.
7. Cross-review with SA-DES-012; request architect, Project Owner, and lead developer approvals through QUESTION tickets; address feedback and progress only when DoD is met.
Related documents: `.ept/docs/deliverables/business_analysis/BA-ANA-013-offline-foundry-knowledge.md`, `.ept/docs/deliverables/architecture/SA-ANA-013-offline-foundry-knowledge.md`, BA-DES-009/010/012, SA-DES-008/009/011, and `.ept/docs/document_index.md`. Deliverables: business design and linked Developer Stories. No UX design sub-task is needed for agent-facing Markdown guidance.
