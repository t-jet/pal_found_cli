## Research Done

Reviewed ADR-001 exit code 7, SRS FR-ERR retry requirements, `RetryHandler` HTTP 429/503 handling, `ErrorSerializer` HTTP status mapping, TESTCASE-003 D-7, and `foundry_datasets_cli.py` exception handlers. Links checked: this question blocks DEV-STORY-005 and asks about TESTCASE-003.

## Answer

The `OSError errno in (11, 115)` rate-limit heuristic is not the architecture. It should be removed from datasets CLI error handling.

Required behavior:
- HTTP 429 classification belongs in common retry/error handling, not per-skill `OSError` guessing.
- `RetryHandler` must retry SDK exceptions that expose HTTP 429 or 503.
- After retries exhaust, `ErrorSerializer` must emit `RateLimitExhausted`, exit 7, for real SDK HTTP 429 exceptions.
- Datasets CLI should return the code produced by `ErrorSerializer`; it must not return a different code than the stdout envelope says.
- Plain `OSError` remains configuration/transport handling unless it carries a real HTTP status.

## Resolution

QUESTION-021 is answered. Add tests with a Foundry SDK style 429 exception or a mock carrying the same status attributes. Do not keep errno 11/115 as rate-limit proof.
