## Research Done

Reviewed SRS-001 binary limits, SAD-001 binary/download components, ADR-003 binary upload note, TESTCASE-003 D-5, and `foundry_datasets_cli.py` upload code. Links checked: this question blocks DEV-STORY-005 and asks about TESTCASE-003.

## Answer

Unbounded `fobj.read()` is not acceptable. The datasets file upload path needs a size guard before reading local content into memory.

Architecture decision:
- Prefer SDK-native streaming upload or file-object upload if the SDK supports it.
- If the SDK only accepts bytes, call `Path(file_path).stat().st_size` before reading.
- Introduce `FOUNDRY_AGENTIC_CLI_MAX_UPLOAD_BYTES` as the upload guard. Default: `1572864`, matching the conservative binary download default until Product Owner sets a separate upload limit.
- If the file exceeds the limit, return ADR-001 user input error, exit 1, with a JSON error envelope on stdout.
- Do not partially upload. Upload is all-or-reject.
- Keep `FileNotFoundError` mapped to exit 4.
