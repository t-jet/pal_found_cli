## Research Done

Reviewed SRS-001 FR-ASYNC-3, ADR-002, SAD-001 timeout sequences, `RetryHandler.execute`, TESTCASE-003 D-9, and `foundry_datasets_cli.py` main dispatch. Links checked: this question blocks DEV-STORY-005 and asks about TESTCASE-003.

## Answer

The question is partly right but needs a narrower fix. Datasets CLI does use `RetryHandler.execute`, and that helper wraps calls in `asyncio.wait_for()`. The defect is that the resolved per-call timeout is passed only to the SDK as `request_timeout`; it is not passed to `RetryHandler`.

Required behavior:
- Resolve timeout once: CLI `--timeout` wins, otherwise `cfg.timeout_s`.
- Instantiate `RetryHandler(timeout_s=timeout)` or pass the same value into the wrapper by an equivalent common API.
- Continue passing `request_timeout=timeout` to the SDK. SDK timeout and wrapper timeout should match.
- If the wrapper times out, return ADR-001 timeout error, exit 5, with JSON error envelope on stdout.
- Add a test where the SDK coroutine sleeps longer than the configured timeout and verify exit 5.

## Resolution

QUESTION-023 is answered. Keep the common wrapper architecture; fix datasets wiring so `--timeout` controls both SDK request_timeout and `asyncio.wait_for()`.
