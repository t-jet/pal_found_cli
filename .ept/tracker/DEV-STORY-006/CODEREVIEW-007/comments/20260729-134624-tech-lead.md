## Findings

### Major: paginated filesystem operations do not consume the SDK iterator

Evidence:
- `src/foundry_cli/filesystem/scripts/foundry_filesystem_cli.py:83-90`, `150-157`, `217-224`, `251-258`, and `290` classify these operations as paginated: `folder.children`, `project.organizations`, `resource.markings`, `resource_role.list`, and `space.list`.
- `src/foundry_cli/filesystem/scripts/foundry_filesystem_cli.py:485-493` passes each paginated SDK response into `PaginationHelper.paginate()` through `_single_page()` and `_invoke()`.
- `src/foundry_cli/filesystem/scripts/foundry_filesystem_cli.py:467` only awaits awaitables. Installed `foundry-platform-sdk 1.101.0` returns `foundry_sdk._core.resource_iterator.AsyncResourceIterator` for `Space.list`, `Folder.children`, `Project.organizations`, `Resource.markings`, and `Resource.Role.list`; that object is not awaitable and must be consumed with async iteration.
- `src/foundry_cli/common/pagination_helper.py:124-130` extracts only dict/list/objects with `items`; an `AsyncResourceIterator` has no `items`, `next_page_token`, or `nextPageToken`, so it is treated as one item and pagination stops.
- `tests/test_foundry_filesystem_cli.py:228-246` mocks paginated SDK calls as `AsyncMock` returning dict page envelopes. That does not match the real SDK return type and misses the bug.

Observed SDK check:

```text
foundry-platform-sdk 1.101.0
Space.list(...) -> foundry_sdk._core.resource_iterator.AsyncResourceIterator
awaitable False
async_iter True
items_attr False
next_token_attrs False False
```

Impact:
- The five paginated filesystem commands print the iterator object instead of resources, or serialize a list containing the iterator object.
- `--batch-pages`, `--page-token`, metadata emission, and TOON/JSON output semantics are wrong for these commands against the real SDK.
- This violates the CODEREVIEW scope for SDK operation correctness and pagination behavior.

Required correction:
- Update filesystem pagination handling to consume `AsyncResourceIterator` responses correctly. Prefer a shared helper-compatible adapter or direct async iteration that preserves `--page-size`, `--page-token`, `--batch-pages`, and stderr pagination metadata. If the SDK iterator does not expose next-token metadata, document and implement the closest supported behavior without emitting false tokens.
- Add tests using a test double with `__aiter__` matching the SDK return protocol, not only dict page envelopes.
- Keep existing coverage for dict/list page envelopes only if still needed for shared helper compatibility.
