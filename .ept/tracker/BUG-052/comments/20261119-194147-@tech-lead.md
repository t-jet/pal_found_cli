## Root cause
Released SDK 1.79/1.101/1.111 creates a custom httpx transport, so httpx does not discover environment proxies for the CLI client. AsyncClientFactory passed no SDK Config. Controlled local test sent no CONNECT and failed direct target DNS; explicit Config(proxies={"https": ...}) reached the proxy.

## Fix and limits
- In isolated current-main tool checkout at 01cd9e91, factory reads standard proxy environment via urllib.request.getproxies_environment and applies proxy_bypass_environment to the configured Foundry host. Passes selected HTTP/HTTPS values through public SDK Config(proxies=...). Scheme-specific settings beat ALL_PROXY; lowercase wins over uppercase; Python CGI guard ignores uppercase HTTP_PROXY. Bare proxy host:port uses http://. No applicable proxy retains default direct client. Invalid proxy URL raises a generic ConfigurationError without printing credentials.
- NO_PROXY supports wildcard, exact host, domain boundary/leading dot, explicit host:port and exact IP per urllib. CIDR is unsupported. Client-level bypass is selected for the configured host; redirects to another host retain that selection. README documents both limits. Existing auth, preview and client creation flow remain intact.
- Four source files: README.md, src/pal_found_cli/common/async_client_factory.py, tests/test_async_client_proxy.py, tests/test_pal_found_aip_agents_cli.py. Root independently checked raw hashes in .ept/tmp/bug052_root_source_gate_20261119.json; final factory SHA256 98659C3BAA2E8C4F5894663FE7E136D8243E794A6B2F0E2C730C301A738EFA19.
