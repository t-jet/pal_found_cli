## Root cause

`.ept/tools/tracker/tracker/comments.py::create_comment` built the comment identity as `f"{datetime.now():%Y%m%d-%H%M%S}-{author}"` and then wrote it with `open(path, "w")`. The stamp has only second granularity and there was no collision check, so a second write by the same author in the same second resolved to the same file path and truncated the earlier comment. `tickets.update_ticket` (`tracker/tickets.py` line 431) writes its automatic "Ticket updated" comment through the same function, so any field/status write within the same second as a substantive approval comment replaced that approval.

## Fix

In `.ept/tools/tracker/tracker/comments.py`:
- **New constant (line 17):** `_MAX_COMMENT_ID_ATTEMPTS: int = 10_000` — bound on the suffix search.
- **`_parse_comment_metadata` (line 82):** id regex changed to `^(\\d{8}-\\d{6})-(.+?)(?:_\\d{3})?$` so a suffixed id still reports the full author and the base timestamp in listings.
- **`create_comment` (lines 100-153):** derive `base_id` (line 121), then allocate a unique id in a retry loop that opens the file with exclusive mode `"x"` (line 138). On `FileExistsError` the writer bumps a numeric suffix and retries with `f"{base_id}_{suffix:03d}"` (line 149), up to the attempt bound. `_` sorts after `.`, so suffixed ids keep chronological order in `list_comments`, and zero-padding keeps `_002` < `_010`.

## Files and lines changed
- `.ept/tools/tracker/tracker/comments.py` lines 17, 82, 100-153 (fix).
- `.ept/tools/tracker/tests/test_comments.py`: new `TestSameSecondWrites` class + `frozen_clock` fixture (regression tests).

## Why existing references stay valid
- The first write for a given second+author keeps the original `YYYYMMDD-HHMMSS-author` id unchanged, so existing comment references remain valid; only colliding (previously overwritten) writes gain a `_NNN` suffix.
- Supported CLI behavior is unchanged: `comment create`, `comment list`, `comment get`, `comment update` all still accept the same ids, and `comment get`/`comment update` accept both base and suffixed ids.
