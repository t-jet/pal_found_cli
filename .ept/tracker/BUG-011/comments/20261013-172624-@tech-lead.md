# Review findings
P2: `pal_found_ontologies_cli.py:1122-1141` uses item-count fallback when raw client and SDK `_page_iterator` are absent. With page_size 2 and an iterator page [1,2,3] plus cursor p2, `_iterator_page` returns [1,2], cursor p2, and leaves 3 unread. Resuming at p2 skips 3. Read-only local probe produced `returned_page={items:[1,2],next_page_token:p2}` and `unreturned_from_page=[3]`. Fail closed when page boundaries cannot be read, as Admin and Filesystem collectors do. Do not use item count as page boundary.
P2: `main` passes one mutable PaginationHelper into RetryHandler around the entire batch. `PaginationHelper.paginate` increments counters before a later page can fail. Retry starts the batch again with the same helper; metadata counts earlier failed-attempt pages. Read-only probe: page 1 returned [1], page 2 timed out once, retry returned [1,2]; stdout items 2, metadata pages_fetched=3 and total_items=3. Reset counters per attempt or retry each page without carrying failed-attempt accounting. This also affects Admin and Filesystem.
No P1 found in raw response path against local SDK source commit 2da67907; its async raw wrapper returns a decoded one-page model. BUG-013 typed key, BUG-017 scalar attribution, and BUG-018 serializer return match the local SDK and ADR-001. Independent QA PASS remains valid for covered cases, but these P2 paths need correction or explicit release limitation.
