## Research Done

Reviewed SRS-001 FR-ERR-1 and access-control acceptance criteria, SAD-001 access-control sequence, ADR-001 exit code 8, TESTCASE-003 D-8, `AccessControlError`, `ErrorSerializer`, and datasets CLI catch blocks. Links checked: this question blocks DEV-STORY-005 and asks about TESTCASE-003.

## Answer

AccessControlError must use the ADR-001 envelope and exit code 8. The current direct catch pattern is only valid if the serializer also emits exit code 8.

Required behavior:
- Register `foundry_cli.common.access_control_guard.AccessControlError` in `ErrorSerializer` as exit 8.
- Datasets CLI should return `serializer.serialize(exc)` instead of hardcoding `EXIT_ACCESS_CONTROL`, so process exit code and stdout envelope cannot diverge.
- Stdout envelope must contain `error`, `exit_code`, `exit_code_name`, `message`, `exception_type`, `traceback`, and `call_id`.
- Expected values: `exit_code=8`, `exit_code_name="AccessControlError"`, `exception_type="AccessControlError"`.
- This should be common-library behavior, then covered by datasets tests.

## Resolution

QUESTION-022 is answered. TESTCASE-003 should assert both return code and JSON envelope fields for AccessControlError.
