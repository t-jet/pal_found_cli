### Test cases (Given/When/Then)
**TC-044-01 inventory one-to-one (AC-D-013-08).** Given the 33 frozen keys, when record headings are enumerated in references/01-dataset.md, 02-branch.md, 03-file.md, 04-transaction.md and 05-view.md, then every key has exactly one record and no extra or duplicate record exists.
**TC-044-02 record completeness sample (AC-D-013-02..05).** Given dataset.create, dataset.get, branch.create, file.upload, file.content, transaction.create, transaction.commit, view.create and view.add_primary_key, when each is read, then resource, effect and side effect, input meaning, result and failure interpretation and a coherent example are correct against the installed CLI.
**TC-044-03 offline copied-folder representative run (AC-D-013-06,07).** Given the copied folder with no network, when a novice agent follows one example per client with mock or recorded output, then it chooses valid inputs, interprets the result and next operation, and every required local link resolves.
**TC-044-04 install prerequisite (BR-012-09).** Given pal-found-datasets/SKILL.md, when the install block is read, then it names pal_found_cli and gives conda `-c t-jet`, pip and uv commands.
**TC-044-05 300-line leaf limit (SA-DES-012).** Given every markdown part, when line counts are checked, then each part is at most 300 lines.
**TC-044-06 transaction lifecycle semantics (AC-D-013-03,05).** Given transaction.create requires `--transaction-type` SNAPSHOT, APPEND, UPDATE or DELETE, when the record is read, then it states the effect on the branch view, that files become visible only after transaction.commit, that transaction.abort discards the change, and how a pending or unknown outcome is distinguished from a committed one.
**TC-044-07 download semantics (AC-D-013-04,09).** Given dataset.read_table requires `--table-format ARROW` or `CSV` and file.content, when the records are read, then the saved bytes location under the download root, the meaning of `--output` as a filename only, and any size limit are stated.
**TC-044-08 paging and empty results (AC-D-013-04).** Given dataset.get_schedules, when a short page with a returned token is read, then the empty or short page is distinguished from end of data and the token follow-up is documented.
**TC-044-NEG-01 missing or duplicate record.** Given a key with no heading or two headings, when the inventory check runs, then it fails naming the key.
**TC-044-NEG-02 unsupported call.** Given an operation not in the register, when the skill is read, then it is not presented as callable.
**TC-044-NEG-03 stale example.** Given an example selecting a different resource.operation than its heading, when parsed, then it fails.
**TC-044-NEG-04 unresolved link.** Given a relative link that escapes the folder or targets a missing file, when resolved, then it fails.
