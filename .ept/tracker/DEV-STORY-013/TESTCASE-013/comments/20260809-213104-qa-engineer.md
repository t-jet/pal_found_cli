## QA test case design plan

### Objective
Design an executable, traceable QA test-case suite for DEV-STORY-013 covering all 23 foundry-models operations and all 15 story acceptance criteria, matching the canonical TESTCASE-010/011/012 structure.

### Scope
- Catalog/parser/help for all 23 commands; exact nested SDK routing (LiveDeployment, Model, Model.Version, Model.Experiment, Model.Experiment.Series, Model.Experiment.ArtifactTable, ModelStudio, ModelStudio.ConfigVersion, ModelStudio.Run, ModelStudio.Trainer).
- JSON argument validation (model-version create, experiment search, config-version create, transform-json input) before client creation.
- Exactly 4 cursor-paged commands via PaginationHelper (experiment search, model-version list, model-studio-config-version list, model-studio-run list); offset/page_size as service slicing only; trainer list has no pagination flags.
- 3 streamed downloads (series parquet, artifact-table json/parquet) via BinaryDownloadHandler: atomic persistence, metadata envelope, bounded memory, response closure, unsafe-name rejection.
- AccessControlGuard precedence: global → namespace → operation; read-only blocks write set (transform_json, creates, promote_version, launch); experiment search stays semantic read; launch/promote write classification regression.
- Metadata-only tier exact 12 permitted / 11 blocked; fail closed on missing/malformed packaged policy.
- include_attribution=False; B3 tracing enabled/disabled/retry-stable/restore; no W3C.
- Retry behavior: transient-only, cursor-local state, at-least-once disclosure for mutating/inference ops.
- ADR-001 error taxonomy, ADR-002 timeouts, ADR-004 output formats (json/toon/auto), ADR-005 NDJSON stderr, privacy/confidentiality.
- Packaging: console entry point, Claude skill launcher, wheel/editable installs from arbitrary CWD, entry-point preservation, regression gates (Python 3.11/3.12, ruff, mypy, bandit, >=80% coverage).

### Approach
- One scenario per distinct behavior path in Given/When/Then format, with Type labels (positive, negative, boundary, security, resilience, structural, packaging) and smoke/environment labels consistent with siblings.
- Each case defines: command/function under test, prerequisites/fixtures, steps, expected stdout/stderr/exit code, filesystem effects, cleanup, evidence mapping to DESIGN-013 and story ACs.
- A traceability matrix maps every story AC to one or more test cases.
- Deliverable: .ept/docs/deliverables/qa/TESTCASE-013-test-cases.md; document_index.md updated.
- Evidence: this plan comment, the case-set comment, and registration in the document index. No live Foundry service access; mocked SDK fakes for routine evidence with optional approved non-production smoke.

### Review
- Tech lead reviews the completed case set and records approval before TESTEXEC-013 starts (per sibling pattern).
