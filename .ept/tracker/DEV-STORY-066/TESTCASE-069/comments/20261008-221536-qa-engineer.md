## Scope
DEV-STORY-066; T20-T25; source-blind J7 and J8 prompts in pal_found_cli_skills/tests/fixtures/feature015_qa/reader_prompts.json. Six rubric dimensions and topic mapping are in reader_coverage.json. Approved BA-DES-015 and SA-DES-014 define expected behaviors. Reader receives isolated pal-found-dev plus prepared versions and synthetic data, without source oracle or public documentation.

## Preconditions
- OSDK 2.x generated Todo/Action bindings and exact dependency versions, public OAuth callback/origin, two identities with distinct grants, local React fixtures.
- Widget Set with two entry points, typed parameter/event schema, Playground/Workshop fixture, initial host version and authorized publication route. Tenant registration, live OAuth, publication and grants are outside fixture proof.

## Given/When/Then scenarios
- J7-1: Given prepared binding and permitted user, when reader creates client and loads a bounded Todo page, then code/configuration names exact resources and shows loading, empty, success and error states.
- J7-2: Given valid login but denied Action grant, when completion is attempted, then denied state remains visible; reader identifies user, app and scope boundaries without broadening grants.
- J7-3: Given timeout after Action submission, when effect is uncertain, then reader performs a fresh authorized read before considering replay.
- J8-1: Given no first release, when Widget Set is previewed, then reader distinguishes local/dev preview from a published version and describes first release prerequisite.
- J8-2: Given two widgets and typed Workshop parameters/events, when one widget emits an event, then host and second widget receive only schema-valid values; wrong type is rejected.
- J8-3: Given new published release but old host selection, when delivery is checked, then reader selects/verifies exact host version and states rollback to prior version.

## Edges and negative data
Empty object page, missing generated binding, canceled request, denied app resource, invalid event type, second widget asset, stale host version, unpublished first release. Use bounded requests and no token logging.

## Expected outputs and review
For each scenario score capability, prerequisites/identity/access, ordered procedure, adaptable input/result, observable validation, and bounded recovery with exact local headings. Every dimension must pass; a missing essential fact fails. Execute provided Node/TypeScript fixtures as applicable and record command exit/output; fixture results do not prove tenant deployment. Tech Lead or Architect review of this case design is required before TESTEXEC execution or QA sign-off.
