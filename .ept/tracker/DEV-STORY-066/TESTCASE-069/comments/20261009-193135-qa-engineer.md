## Four required acceptance paths
These extend the 20261008-221536-qa-engineer case design. Each has a prepared local fixture and a separate enrollment boundary. Expected result is a decision/artifact, not a claim that a tenant action ran.

### J7-4: denied OAuth before query
Given the public client has a prepared callback/origin and two identities, with one missing enrollment/app grant or an invalid callback/scope, when the reader attempts sign-in and initial Todo query, then it must show a distinct login/callback/scope failure, make no Action call, preserve no secret in browser assets, and identify the exact registration or grant owner. Local artifact: `examples/applications/client.ts` configuration plus a fake-auth state trace asserting the failure before query. Live OAuth registration, origin and grants require authorized enrollment/admin action.

### J7-5: Action result, cache refresh and deployed result
Given an authorized Todo and a completed Action response, when the reader applies completion, then it must retain pending/error/validation states, invalidate or refetch the affected OSDK query cache, account for subscription or refresh updates where configured, and verify the refreshed Todo result before claiming the UI changed. A local fixture should show the old row, confirmed Action result and refreshed filtered list; a timeout leaves effect unknown until authorized reread. Given local preview and a selected website release, then the reader must distinguish a preview/build artifact from the deployed version and verify expected assets and both permitted/denied user views after deployment. Local UI state fixture is evidence only; Action, subscription, publication and website checks need enrollment access.

### J8-4: host parameter and event roundtrip
Given Workshop owns a numeric count parameter, when the host sends 0 then 5 to the widget, then the widget renders those exact values; when it emits `countChanged` with 6, then Workshop updates its bound value and a second widget receives the resulting state. An undeclared or string count payload must be rejected without changing host state. Local artifact: `examples/widgets/fixture_run.mjs` plus parameter/event schema and a trace of host→widget→host→second widget states. Actual Workshop binding and grants need enrollment.

### J8-5: verified rollback
Given releases 1.0.0 and 1.1.0 and a host pinned to 1.1.0, when 1.1.0 regresses, then the reader selects previously verified 1.0.0 in Workshop and checks the host version, assets, parameter/event binding and rendered behavior after selection. Source checkout or Widget Set publication alone is insufficient; prior Ontology Actions are not undone. Local release-selection fixture proves the decision only; version selection and host behavior require authorized enrollment.
