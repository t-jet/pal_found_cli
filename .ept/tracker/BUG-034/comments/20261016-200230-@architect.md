## Architecture correction, 2026-10-16
- Approved DESIGN-020 says preview parameters are excluded. Its six operation count and nested CheckReport dispatch remain correct, but the exclusion conflicts with the published Data Health endpoint contract.
- Palantir API reference for Create, Delete, Get and Replace Check and Get and Get Latest Check Reports states that use requires preview=true. The endpoint schema calls preview optional, while the usage warning and request examples require it.
- Installed foundry-platform-sdk 1.101.0 exposes preview: Optional[bool] on all six methods. The released tool at b9c5f8a omits preview from OP_SPECS and SDK kwargs. Independent QA captured an omitted query and a request with ?preview=true through MockTransport. No enrolled tenant call occurred.
- For this pinned API baseline, pass preview=True through all six CLI SDK dispatches without adding an operation or user flag. Keep _sdk_internal excluded. Preserve existing ACL, write classification, metadata policy, retry, timeout, payload and result contracts. Recheck the requirement when SDK/API baseline changes.
- Verification: six wire requests must contain exactly preview=true; existing inputs and access controls still pass; offline skill examples must disclose preview behavior; independent QA must retest before FEATURE-012 remediation or FEATURE-015 acceptance. TESTCASE-020 currently forbids preview and needs QA correction.
