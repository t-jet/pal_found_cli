# Independent QA design, 2026-10-14

## Scope

BUG-032 cross-process link ID allocation, index preservation, and safe removal through tracker CLI. Include shared counter interaction with concurrent ticket creation. Review current tracker index.py, links.py, tickets.py, CLI exit taxonomy, and TASK-006 context.

## Preconditions and test data

Build isolated tracker fixture under .ept/tmp using tracker test scaffold config. Set EPT_TRACKER_ROOT_PATH to fixture tracker root for every CLI subprocess. Use one source TASK, eight distinct target TASKs, RelatesTo links, distinct worker markers, and bounded start gate. All ticket/link operations use documented tracker_cli.py create, link create, link list, link remove, and get commands. Production tracker state remains untouched.

## Scenarios

1. Given eight targets and eight waiting CLI processes, when gate opens and each creates a distinct source-to-target link, then all eight exit 0, return eight distinct LINK IDs, and link list retains exactly eight target rows. Repeat burst to check continuing IDs and no lost rows.
2. Given one existing source/target set, when ticket create and link create CLI processes start together, then both exit 0; follow-on ticket and link creates return new IDs, all created tickets remain get-readable, and all links remain list-visible. This checks shared counter writes.
3. Given eight retained links, when link remove targets one returned ID, then exit 0 and only that target row disappears; seven remain.
4. Given two concurrent attempts for the same source, target, and RelatesTo type, when both run, then exactly one exits 0 and one exits 2 with Link already exists; link list has one row.
5. Given a legacy duplicate ID in isolated unit fixture, when remove_link is called, then ValidationError says ambiguous and both rows remain. Execute existing focused regression test; CLI cannot create malformed duplicate rows by design.

## Edges, negative paths, outputs

Use empty initial link index and two consecutive bursts. Invalid or missing ticket IDs and duplicate pair return validation exit 2; successful CLI calls return 0. No auth, network, payload-size, or remote timeout path applies to local tracker persistence. Bound process startup and lock wait to current 20/30 second test defaults; unexpected exit, timeout, duplicate ID, missing row, or wrong removal is FAIL and requires defect follow-up. Capture each invocation, exit code, stdout/stderr, returned ID, and final CLI list count. No live service call.
