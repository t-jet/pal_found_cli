Concurrent link creates read the same counter and overwrite a shared CSV index, producing duplicate LINK-01949. Link create/remove now use a cross-process transaction lock; index/counter writes use atomic replacement, ID allocation recovers from indexed maxima, and ambiguous duplicate-ID removal is refused. Tech Lead found a second path where concurrent ticket creation overwrote link counters; ticket creation is serialized and counter writes merge maxima under a shared lock. Windows replacement retries short reader sharing conflicts. Tracker suite passed 437/437, Ruff passed, and independent QA passed five scenarios including two 8-link bursts, mixed ticket/link concurrency and targeted removal (20261014-171207-@qa-engineer). The original collided links were repaired via CLI as LINK-01950/01951. No blocker links.
