## Finding
`create_link` now holds `interprocess_lock("links")` while reading and replacing the link CSV and shared `.id-counters.yaml`. `create_ticket` in `tickets.py` still calls `get_next_ticket_id` and `increment_counter` without this lock, and `increment_counter` writes the same YAML. A concurrent ticket create can load stale counters and overwrite the new link counter, or the link update can overwrite the ticket counter. Link ID recovery from CSV limits link reuse, but ticket ID allocation can reuse a number and overwrite an existing ticket file. Use one shared counter transaction lock for both creators, or separate counter files, and test concurrent ticket plus link creation before closure. Current 8-link test covers link-link concurrency only.
