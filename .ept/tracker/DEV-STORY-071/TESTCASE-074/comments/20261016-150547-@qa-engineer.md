## Scope and status
DEV-STORY-071, all 27 IDs in partition R1: Group (8), GroupMember (3), GroupMembership (1), GroupMembershipExpirationPolicy (2), GroupProviderInfo (2), User (9), UserProviderInfo (2). This is a draft; Tech Lead or Architect approval is required before formal TESTEXEC-074.

## Preconditions and data
Frozen foundry-platform-sdk 1.101.0, prepared Python/httpx, isolated MockTransport and denied public sockets. Use distinct synthetic group, user, organization and provider IDs; a policy with a nonempty maximumDuration; groups with and without multipass attributes; active and deleted users. No enrollment mutation or permission claim.

## Given/When/Then scenarios
- Given each of the 27 SDK methods and its local guide, when called through the prepared SDK, then method, path, query, aliases, body, timeout, response type and declared error match frozen source; ordinary/raw/streaming/async forms use their actual return and cleanup contracts.
- Given Group create/get/get_batch/list/list_current/replace/search/delete, when synthetic responses include matching and missing identities, then returned IDs and organization visibility are checked; replace preserves multipass fields and uncertain create/delete outcomes remain unretried until reconciled.
- Given GroupMember add/list/remove and GroupMembership.list, when direct and transitive members differ, then selected group/user identities, expiration filters and continuation are interpreted correctly; transitive=true plus includeExpirations=true yields the declared error.
- Given expiration-policy and provider-info get/replace, when existing limits and mappings differ, then replacement sends intended values and result is compared; protected realm, permission and not-found errors stay distinct.
- Given User delete/get/get_batch/get_current/get_markings/list/profile_picture/revoke_all_tokens/search and UserProviderInfo get/replace, when active/deleted identities, token revocation and binary payloads are modeled, then exact IDs, statuses, marking lists, bytes, provider IDs and named errors are checked.

## Edges, negatives and expected outputs
Batch sizes 1 and 500 accepted; 0 and 501 rejected by SDK validation. Empty intermediate pages, repeated continuation tokens, max page/item budgets and partial results are explicit. Test invalid group organizations, missing IDs, denied access, malformed body, timeout and transport failure. For each operation use source-oracle response schema and error name/parameters; successful void methods return None and profile_picture returns bytes. Request timeout 30 seconds; finite page/deadline budgets. Automated fixture process exits 0 only when assertions pass; nonzero is failure. Record actual vs expected for every case and open BUG-SUB on any failure.
