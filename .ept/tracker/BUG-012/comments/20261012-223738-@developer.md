Root cause: both collectors stopped after page_size * batch_pages items, then returned the SDK cursor for the complete fetched page. An oversized page left unreturned items behind; short pages made item-count-derived pages_fetched inaccurate.
Fix: Admin and Filesystem now collect complete SDK pages through AsyncResourceIterator._page_iterator, stop after batch_pages actual pages or terminal cursor, and report actual pages_fetched and total_items. Missing SDK page boundaries raise a clear error instead of returning a cursor that could skip records.
Evidence: SRS-001 FR-PAG-2/4 and DESIGN-009 pagination reviewed. Focused Admin and Filesystem suites: 346 passed. Ruff check and git diff --check passed. Tests cover oversized pages (Admin 3/2, Filesystem 150/100), short pages, empty pages, batch limit, and cursor resume without lost items. Independent QA retest requested.
