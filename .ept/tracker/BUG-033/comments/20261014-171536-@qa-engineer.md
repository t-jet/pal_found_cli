# QA retest design, 2026-10-14

## Scope and preconditions

Retest Windows PermissionError during atomic counter-file replacement in BUG-033, plus BUG-032 mixed ticket/link race. Use current Windows workspace code, Python, tracker CLI, and fresh isolated `.ept/tmp` fixtures. No production tracker storage mutation. BUG-032 design comment 20261014-170920-@qa-engineer and Tech Lead approval 20261014-170939-@tech-lead cover unique ID and row checks.

## Scenarios

1. Given isolated tracker fixture and four ticket plus four link subprocesses at one gate, when all create concurrently, then every child exits 0, four unique ticket IDs and four unique link IDs persist, both counters advance, and no FileOperationError appears. Repeat ten runs with fresh fixtures to expose intermittent Windows sharing failures.
2. Given CLI-only fixture with eight repeated ticket/link race pairs and follow-on creates, when processes run, then every exit is 0, ticket IDs stay unique and get-readable, link IDs stay unique, and all links remain list-visible.
3. Given entire tracker test suite, when it runs on Windows with `.ept/tmp` basetemp, then exit 0 and all tests pass, including concurrent mixed create. Run twice if first pass to check intermittent failure.

## Edges, negatives, expected output

Temporary Windows PermissionError at a counter-file read must be retried within existing bounded file policy. Persistent file access failure must return FileOperationError exit 4 rather than hang; inspect targeted error path without mutating production data. Successful CLI operations return exit 0. Unexpected nonzero exit, duplicate ID, missing row, lost counter progress, timeout, or failed full suite is FAIL and requires defect follow-up. Auth and network cases do not apply. Capture commands, exit codes, counts, and traceback on failure.
