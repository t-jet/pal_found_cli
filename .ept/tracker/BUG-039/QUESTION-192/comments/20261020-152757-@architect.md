## Narrow correction to terminal-error verification

The verification paragraph in architect answer 20261020-103158-@architect used an overbroad phrase, "exit7 retryable HTTP exhaustion". Replace that phrase with the following precise oracles: terminal timeout remains exit5; HTTP429 exhaustion remains exit7 (RateLimitExhausted); HTTP503 exhaustion retains existing exit6 (ServerError). Do not expand exit7 to all retryable HTTP statuses.

Evidence: ADR-001 defines exit7 specifically for HTTP429 exhaustion. Its server row excludes503 while retried, leaving exhausted503 wording ambiguous; this answer does not invent an ADR-wide taxonomy change. Pinned tool0963 common/error_serializer.py explicitly maps status429 to EXIT_RATE_LIMIT7 and status503 to EXIT_SERVER_ERROR6. Root independent probe confirms that distinction. BUG039/040 change timeout precedence, bounds and total attempt count while preserving this existing terminal mapping. Any later taxonomy change requires its own approved decision and regression scope.

All other QUESTION192 timeout/count decisions remain as recorded. This appendix corrects the verification sentence and makes no implementation QA or release-completion claim.
