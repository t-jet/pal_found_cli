### Test cases (Given/When/Then)
**TC-049-01 inventory one-to-one (AC-D-013-08).** Given the frozen keys, when record headings are enumerated in each namespace SKILL.md and references, then all 24 keys have exactly one record each and no extra or duplicate record exists.
**TC-049-02 record completeness sample (AC-D-013-02..05).** Given agent.get, session.create, session.streaming_continue, session_trace.get, content.get, query.execute, query.streaming_execute, query.get_by_rid, anthropic_model.messages and open_ai_model.embeddings, when each is read, then resource, effect and side effect, input meaning, result and failure interpretation and a coherent example are correct against the installed CLI.
**TC-049-03 offline copied-folder representative run (AC-D-013-06,07).** Given the copied folders with no network, when a novice agent follows one example in each of the three namespaces with mock or recorded output, then it chooses valid inputs, interprets the result and next operation, and every required local link resolves.
**TC-049-04 install prerequisite (BR-012-09).** Given the three SKILL.md files, when the install blocks are read, then each names pal_found_cli and gives conda `-c t-jet`, pip and uv commands.
**TC-049-05 300-line leaf limit (SA-DES-012).** Given every markdown part of all three folders, when line counts are checked, then each part is at most 300 lines.
**TC-049-06 session lifecycle semantics (AC-D-013-03,05,09).** Given session.create, session.streaming_continue, session.blocking_continue, session.cancel, session.delete, session.update_title and session_trace.get, when the records are read, then the effect of each session step, the distinction between streaming and blocking continuation, and how a pending or unfinished session result is handled are stated.
**TC-049-07 inference payload semantics (AC-D-013-03,04).** Given anthropic_model.messages, open_ai_model.embeddings and query.execute, when the records are read, then the structured JSON input form, the returned content or vector meaning, and any attribution or cost limit are stated.
**TC-049-NEG-01 missing or duplicate record.** Given a key with no heading or two headings, when the inventory check runs, then it fails naming the key.
**TC-049-NEG-02 unsupported call.** Given an operation not in the register, when the skill is read, then it is not presented as callable.
**TC-049-NEG-03 stale example.** Given an example selecting a different resource.operation than its heading, when parsed, then it fails.
**TC-049-NEG-04 unresolved link.** Given a relative link that escapes the folder or targets a missing file, when resolved, then it fails.
