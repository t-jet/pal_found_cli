## REST connectivity QA finding
The local Connection guide now states that Snowflake External OAuth needs a preexisting security integration, trusted authorization server and matching issuer/audience/Connection RID claims; key-pair mode needs a matching public key already registered to the Snowflake user. STS role mode needs an existing AWS trust policy and ability to assume the role. Connection.create consumes supplied configuration; it does not provision those upstream identities. Evidence: pal-found-dev/references/rest/v2/connectivity/Connection.md lines 11-13 and linked local model pages.

Acceptance case: Given syntactically valid create input but no upstream credential/trust provisioning, when an offline reader plans Connection.create, then the reader names the dependency and stops before submission; it must not infer that a successful model validation grants access. Given prepared authorized credentials, verify exact configuration shape and response with mock transport, then label live connection verification as enrollment/administrator work. Current local prose meets this conditional boundary on inspection; no live Snowflake or AWS tenant test has run.
