### Test cases (Given/When/Then)
**TC-051-01 inventory one-to-one (AC-D-013-08).** Given the frozen keys, when record headings are enumerated in each namespace SKILL.md and references, then all 25 keys have exactly one record each and no extra or duplicate record exists.
**TC-051-02 record completeness sample (AC-D-013-02..05).** Given build.create, build.get, build.jobs, job.get, schedule.create, schedule.run, schedule.runs, schedule_version.get, sql_query.execute, sql_query.get_status, sql_query.get_results and sql_query.cancel, when each is read, then resource, effect and side effect, input meaning, result and failure interpretation and a coherent example are correct against the installed CLI.
**TC-051-03 offline copied-folder representative run (AC-D-013-06,07).** Given the copied folders with no network, when a novice agent follows one example in each namespace with mock or recorded output, then it chooses valid inputs, interprets the result and next operation, and every required local link resolves.
**TC-051-04 install prerequisite (BR-012-09).** Given the two SKILL.md files, when the install blocks are read, then each names pal_found_cli and gives conda `-c t-jet`, pip and uv commands.
**TC-051-05 300-line leaf limit (SA-DES-012).** Given every markdown part of both folders, when line counts are checked, then each part is at most 300 lines.
**TC-051-06 asynchronous build and schedule semantics (AC-D-013-04,05,09).** Given build.create, build.jobs, build.search, schedule.run and schedule.runs, when the records are read, then the pending build or run state, the job inspection step, the pagination on search and the distinction between a started and a completed run are stated.
**TC-051-07 sql query async lifecycle (AC-D-013-04,05).** Given sql_query.execute, sql_query.get_status, sql_query.get_results and sql_query.cancel, when the records are read, then the execute to status to results ordering, the pending or unfinished interpretation, the result download form and the cancel effect are stated.
**TC-051-NEG-01 missing or duplicate record.** Given a key with no heading or two headings, when the inventory check runs, then it fails naming the key.
**TC-051-NEG-02 unsupported call.** Given an operation not in the register, when the skill is read, then it is not presented as callable.
**TC-051-NEG-03 stale example.** Given an example selecting a different resource.operation than its heading, when parsed, then it fails.
**TC-051-NEG-04 unresolved link.** Given a relative link that escapes the folder or targets a missing file, when resolved, then it fails.
