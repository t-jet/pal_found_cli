## Findings (file:line with code snippets)

### P1 — Medium: `build search` marks SDK-required `where` as optional
- `src/foundry_cli/orchestration/scripts/foundry_orchestration_cli.py:168-174`:
  ```python
  _op(
      "build",
      "search",
      ("Build",),
      "search",
      optional=("where", "order_by", "page_size", "page_token"),
      json_args=frozenset({"where", "order_by"}),
  ),
  ```
- Installed SDK `inspect.signature(AsyncBuildClient.search)` shows `where` with `required=True` (pydantic `validate_call`): `where: Annotated[Union[SearchBuildsNotFilter, ...], FieldInfo(annotation=NoneType, required=True, discriminator='type')]`.
- A user invoking `build search` without `--where-json` triggers a pydantic `ValidationError` (probe confirmed: `ValidationError ... Missing required keyword only argument`). Because `pydantic.ValidationError` is a `ValueError` subclass, `_serialize_error` maps it to exit 1 (UserInput) — the error is caught, exit code is correct per ADR-001, and no secret leaks. But the failure message is the raw SDK text, not the CLI's structured message, and the spec metadata mis-states the contract.
- Note: DESIGN-014's table also lists `--where-json` as optional, so the discrepancy originates in the design. Not a regression vs. design, but worth aligning (either make `where` required in the spec, or accept it optional and document that a server/SDK-side 4xx is possible).
- Recommendation: move `where` to `required` in the OP_SPECS entry so the CLI enforces it before dispatch with its own structured exit-1 message. Non-blocking for this review (runtime failure is graceful), track as follow-up.
