### PL-TC-01: Tool choice
Given a reader starts at SKILL.md with a pipeline task, when they follow the pipeline link and compare Pipeline Builder, Code Repositories and Code Workspaces, then each option has a purpose, prerequisite or limit, and an actionable next step; all local links resolve.

### PL-TC-02: Python and SQL

### PL-TC-03: Release and transaction
Given a pipeline change is tested, when the reader follows Develop, test, and release then Understand builds, dataset branches, and transactions, then branch, release, build and transaction outcomes are distinguished; a successful request is not treated as a completed build; stale or failed state leads to a status check.

### PL-TC-04: Operations diagnosis
Given a failed scheduled output, when the reader follows operations.md Schedule and inspect builds, Use lineage to understand impact, Monitor data quality and service health, and Establish a support path, then guidance identifies schedule/run status, upstream impact, health evidence, branch context and safe escalation without inventing a CLI operation.

### PL-TC-05: Offline and negative navigation
Given a copied pal-found-dev folder with no network, when local links from SKILL.md through pipeline and operations pages are resolved, then all targets stay inside the folder and essential path decisions remain readable; a deliberately broken local target causes a failing check with page and target named.

Edge and negative cases: empty build history or missing permission must be described as an unknown state requiring status or access verification; no fabricated success.
