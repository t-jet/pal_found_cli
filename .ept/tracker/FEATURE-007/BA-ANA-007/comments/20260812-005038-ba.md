Transition target: In Progress. Responsible role: ba. Date: 2026-08-12.

## Business case
Distributing foundry_cli_skills by cloning the repository and copying skill folders gives users a simple, dependency-free installation path: clone once, copy the skills into the target harness. Clear instructions make adoption straightforward.

## Analysis plan
1. Study source requirements (Project Owner architecture-change request 2026-08-11; parent FEATURE-007).
2. Derive finite set of business requirements in business terms.
3. Prepare acceptance criteria in Given/When/Then format.
4. Analyze impact to end-to-end business processes (installation, updates, harness onboarding).
5. Define access restriction changes (source and copy permissions).
6. Document assumptions and risks.
7. Evaluate request rate and data size changes.
8. Produce business analysis deliverable and update document_index.md.

## Acceptance criteria (prepared)
- AC1: Given a user, When they clone the foundry_cli_skills repository, Then they receive all skill content.
- AC2: Given a cloned repository, When the user follows the copy instructions, Then the skills are available in the target harness.
- AC3: Given an update to the skills repository, When a user re-clones or pulls, Then they can refresh their local skills to the latest version.
- AC4: Given a user on any supported harness, When they follow the distribution instructions, Then the instructions are clear and complete.
