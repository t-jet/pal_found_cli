### Test cases (Given/When/Then)
**TC-053-01 inventory one-to-one (AC-D-013-08).** Given the 19 frozen keys, when record headings are enumerated in references/01-lifecycle.md and 02-content.md, then every key has exactly one record and no extra or duplicate record exists.
**TC-053-02 record completeness sample (AC-D-013-02..05).** Given media_set.create, media_set.upload, media_set.upload_media, media_set.commit, media_set.read, media_set.read_original, media_set.get_result, media_set.transform, media_set.get_rid_by_path and media_set.reference, when each is read, then resource, effect and side effect, input meaning, result and failure interpretation and a coherent example are correct against the installed CLI.
**TC-053-03 offline copied-folder representative run (AC-D-013-06,07).** Given the copied folder with no network, when a novice agent follows one example per client with mock or recorded output, then it chooses valid inputs, interprets the result and next operation, and every required local link resolves.
**TC-053-04 install prerequisite (BR-012-09).** Given pal-found-media-sets/SKILL.md, when the install block is read, then it names pal_found_cli and gives conda `-c t-jet`, pip and uv commands.
**TC-053-05 300-line leaf limit (SA-DES-012).** Given every markdown part, when line counts are checked, then each part is at most 300 lines.
**TC-053-06 transaction lifecycle semantics (AC-D-013-03,05,09).** Given media_set.create, media_set.commit, media_set.abort, media_set.clear and media_set.get_status, when the records are read, then the staged versus committed state, the effect of abort and clear, and how a pending or unknown outcome is distinguished from a committed one are stated.
**TC-053-07 binary transfer semantics (AC-D-013-03,04,09).** Given media_set.upload, media_set.upload_media, media_set.read, media_set.read_original and media_set.get_result, when the records are read, then the bounded upload and download limits, the download destination under the download root, and the metadata versus content distinction are stated.
**TC-053-NEG-01 missing or duplicate record.** Given a key with no heading or two headings, when the inventory check runs, then it fails naming the key.
**TC-053-NEG-02 unsupported call.** Given an operation not in the register, when the skill is read, then it is not presented as callable.
**TC-053-NEG-03 stale example.** Given an example selecting a different resource.operation than its heading, when parsed, then it fails.
**TC-053-NEG-04 unresolved link.** Given a relative link that escapes the folder or targets a missing file, when resolved, then it fails.
### Expected outputs
19/19 keys with exactly one record; zero duplicates or extras; completeness sample passes; zero unresolved local links; install block present; every part at most 300 lines; transaction and binary transfer semantics documented.
