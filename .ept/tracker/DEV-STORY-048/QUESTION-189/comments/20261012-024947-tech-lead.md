## Answer

**Ruling:** `examples/check_config_fixture.py` plus its 16 JSON payloads must move out of `.agents/skills/pal-found-data-health`. They are QA artifacts, not reader deliverables, and SA-DES-012 section 2 ("no executable script belongs in a distributed skill folder") is binding for the 18 CLI namespace skills.

The fix is present in the `pal_found_cli_skills` working tree:

- Payloads and harness moved to `tests/fixtures/offline/data-health/` (protected offline fixture area, staged by the topic-acceptance runner).
- `references/check-config.md` reader guidance is now documentation only; the SDK/semantic guidance is stated as static prose.
- The doc-only gate (`test_skill_tree_migration.py::test_namespace_skills_are_documentation_only`) now rejects any executable file or `examples/` dir in a CLI namespace skill.

**Ownership of the move:** `DEV-STORY-048` owns `pal-found-data-health` and this reconciliation is delivered as part of its deployment work. No separate story is created because the change is a documentation and fixture relocation inside the story already in Deployment, not a new feature or capability.

**Why this does not break the offline case:** every configuration contract already ships the complete create and replace JSON inline in `references/check-config/*.md`, and the reader applies the documented semantic checks (the five empty cross-field choices) by reading the contracts. The executable harness was QA evidence of that behaviour, and it is retained beside the other offline fixtures. No reader capability is lost.
