## PASS — Controls verified

### Path and filename security (BinaryDownloadHandler)

**`binary_download_handler.py` L104–107** — double path-traversal guard: checks both `final_path.parent != download_dir.resolve()` and `not final_path.is_relative_to(root)`. Resistant to NFKC-equivalent traversal sequences.

```python
final_path = (download_dir / filename).resolve()
if final_path.parent != download_dir.resolve() or not final_path.is_relative_to(root):
    self._remove_empty_directory(download_dir)
    raise InvalidDownloadError("Download filename escapes configured path")
```

**`binary_download_handler.py` L237–253** — `_safe_filename` rejects NUL (`\x00`), path separators (`/`, `\`), absolute paths, `.`, `..`; applies NFKC normalization; sanitizes to `[A-Za-z0-9._-]`; truncates to 255 chars.

**`binary_download_handler.py` L100–103** — root directory is created with `mode=0o700` and immediately protected by `_restrict_directory()` which calls `os.chmod(root, 0o700)`, bypassing umask on POSIX.

### Atomic write and cleanup (BinaryDownloadHandler)

**`binary_download_handler.py` L112–160** — uses `tempfile.mkstemp` → writes → `target.flush()` + `os.fsync()` → `os.chmod(temp_path, 0o600)` → `os.replace(temp_path, final_path)`. Atomic rename; mode applied before replace.

**`binary_download_handler.py` L162–167** — `BaseException` handler removes both `temp_path` and `final_path` on every failure path. `stream_closed` flag at L152 prevents double-close in the `finally` block.

### Session alias containment (SessionManager)

**`session_manager.py` L329–344** — `normalize_alias` applies NFKC → casefold → whitespace-to-dash → ASCII check → `_ALIAS_PATTERN` → Windows reserved name rejection. Rejects `.`, `..`, path separators, controls, non-ASCII residue, and names up to 64 chars enforced by `{0,62}` in the pattern.

**`session_manager.py` L88–128** — `_AliasLock.acquire`: `msvcrt.locking` on Windows (`LK_NBLCK` for non-blocking), `fcntl.flock` on Unix (`LOCK_EX|LOCK_NB`). Cross-platform with correct mode selection.

**`session_manager.py` L316–320** — `_path` resolves against `session_root.resolve()` and raises `InvalidSessionAliasError` if the result escapes. Defense in depth against alias normalization bypasses.

### Persistence atomicity and compensation (SessionManager)

**`session_manager.py` L384–400** — `_write_locked`: `tempfile.mkstemp` → JSON dump → `os.fsync` → `os.chmod(temp_path, 0o600)` (non-Windows) → `os.replace`. Temp file deleted on `BaseException`.

**`session_manager.py` L214–233** — persistence failure: calls `delete_remote(session_id)` to compensate. If compensation also fails, attaches `diagnostic_metadata` and an `__notes__` entry with `session_id` for tracing orphaned remote sessions.

**`session_manager.py` L178–194** — `test_corrupt_record_is_deleted_without_logging_secret` verifies the `session_token` value does not appear in any log record or its `repr`. DESIGN-005 §4.1 constraint ("must never appear in logs") satisfied.

### B3 context isolation (TracingProvider)

**`tracing_provider.py` L61–73** — uses `ContextVar.set()` returning a `Token`, and `ContextVar.reset(token)` in `finally`. Python's `contextvars` mechanism ensures per-task isolation; reset tokens make restoration independent of nesting order.

**`tracing_provider.py` L48, L59–60** — `validate(context)` is called before any `TRACE_ID_VAR.set()`. Invalid context raises `InvalidTraceContextError` without mutating SDK state.

**`tracing_provider.py` L87–91** — `secrets.token_hex` (CSPRNG) in a nonzero rejection loop. Cannot produce an all-zero trace/span ID.

## DEFECT — Correction required

### D1 (HIGH) — Missing integration test: retry within tracing scope

**File:** `src/foundry_cli/common/retry.py`, lines 486–495  
**Required by:** DESIGN-005 §7 test matrix, row: *"Integration | Retry within tracing scope | Every attempt carries same B3 context"*  
Also required by TESTCASE-005 acceptance criteria: *"retry behavior"* in tracing test list.

`RetryHandler.execute_traced()` is the integration point:

```python
async def execute_traced(
    self,
    tracing: "TracingProvider",
    coro_func: Callable[..., Any],
    *args: Any,
    supplied: "B3Context | None" = None,
    **kwargs: Any,
) -> Any:
    """Execute every retry attempt under one isolated B3 context."""
    with tracing.scope(supplied):
        return await self.execute(coro_func, *args, **kwargs)
```

No test in `test_tracing_provider.py`, `test_exec_retry_error_output_log.py`, or any other test file calls `execute_traced()` or verifies that the B3 context is identical on the first attempt and on subsequent retry attempts. DESIGN-005 explicitly mandates this test case.

**Required fix:** Add a test to `tests/test_tracing_provider.py` (or a dedicated integration test file) that:
1. Creates a `RetryHandler` and a `TracingProvider` with a mock SDK module.
2. Wraps a failing coroutine that succeeds on the second attempt.
3. Asserts that `TRACE_ID_VAR.get()` returns the same value on every attempt.
4. Asserts that all SDK context vars are restored to their prior values after `execute_traced` returns.

### D2 (MEDIUM) — `download_dir` permissions are umask-dependent

**File:** `src/foundry_cli/common/binary_download_handler.py`, line 104  

```python
download_dir = root / str(uuid.uuid4())
download_dir.mkdir(mode=0o700)          # L104 — umask applies here
```

On POSIX, `Path.mkdir(mode=0o700)` calls `os.mkdir` with mode, but the kernel applies `mode & ~umask`. If the process umask includes a bit set in `0o700` (e.g., umask `0o100` removes owner execute: effective `0o600`), the download directory becomes inaccessible to the owner immediately after creation.

Contrast with root protection at L100–103:

```python
root.mkdir(mode=0o700, parents=True, exist_ok=True)
self._restrict_directory(root)   # calls os.chmod(root, 0o700) — umask-bypassing
```

`_restrict_directory` (L255–258) is called on `root` but not on `download_dir`. The protection is inconsistent.

**Required fix:** Call `_restrict_directory(download_dir)` immediately after `download_dir.mkdir(mode=0o700)` at line 104:

```python
download_dir = root / str(uuid.uuid4())
download_dir.mkdir(mode=0o700)
self._restrict_directory(download_dir)   # add this line
```

Add a test that sets `umask(0o177)` (or mocks `os.chmod`), creates a download directory, and asserts the chmod was called with the expected arguments.

## OBSERVATION (LOW) — `_warn_if_many_active` TOCTOU (non-blocking)

**File:** `src/foundry_cli/common/session_manager.py`, lines 433–444

```python
def _warn_if_many_active(self, agent_rid: str) -> None:
    active = 0
    for path in self.session_root.glob("*.json"):
        try:
            raw = json.loads(path.read_text(encoding="utf-8"))
        except (OSError, UnicodeError, json.JSONDecodeError):
            continue
```

Files are globbed and read without acquiring alias locks. A session file may be deleted or replaced between the `glob()` and `read_text()` call. The `try/except` silently discards errors, so this does not cause crashes; however, the active-session count may be incorrect in a high-concurrency scenario. This is a low-severity observation. A comment in the code documenting the intentional best-effort nature of this check would suffice; no code change is mandated.

Two actionable defects block approval:

- **D1** is a mandatory test case from DESIGN-005 §7 and TESTCASE-005. The implementation is correct; the test is absent.

All other acceptance criteria — path containment, schema validation, token security, tracing context isolation, concurrency guards, resource cleanup — are satisfied by the implementation as reviewed.
