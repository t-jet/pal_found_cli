## Architect Decision — Q1: Deployment Prerequisites

### Decision: DEVOPS-004 may proceed with current common components. DEV-STORY-004 is NOT a prerequisite for the foundry-datasets skill.

### Analysis

**Evidence: CLI import analysis** (oundry_datasets_cli.py line 34-44)

The foundry-datasets CLI imports exactly these common components:

| Component | Source Story | Status |
|---|---|---|
| ConfigLoader | DEV-STORY-001 | Implemented ✅ |
| AsyncClientFactory | DEV-STORY-001 | Implemented ✅ |
| ErrorSerializer + exit codes | DEV-STORY-002 | Implemented ✅ |
| OutputFormatter | DEV-STORY-002 | Implemented ✅ |
| LogSetup + METADATA_SEPARATOR | DEV-STORY-002 | Implemented ✅ |
| AccessControlGuard + AccessControlError | DEV-STORY-003 | Implemented ✅ |
| RetryHandler | DEV-STORY-002 | Implemented ✅ |

**Components NOT imported by datasets CLI:**

| Component | Source Story | Relevance |
|---|---|---|
| AuthProvider | DEV-STORY-001 | Template only; not in datasets CLI |
| PaginationHelper | DEV-STORY-003 | Template only; not in datasets CLI yet |
| BinaryDownloadHandler | DEV-STORY-004 | File download — irrelevant for datasets API |
| SessionManager | DEV-STORY-004 | Session persistence — irrelevant for datasets skill |
| TracingProvider | DEV-STORY-004 | W3C trace headers — not needed for datasets operations |

### Answers

**Q1a: Can DEVOPS-004 proceed with current common components (DEV-STORY-001/002/003)?**

**YES.** All seven components imported by the datasets CLI exist in src/foundry_cli/common/ and are sufficient to assemble _foundry_cli_common.py for deployment. The stories being in Development/New status does not block deployment of the skill, since deployment (per SAD-001 §8.2) is a file copy to .claude/skills/ — not a pip package install. The code is present and importable.

**Q1b: Must DEV-STORY-004 also be complete?**

**NO.** BinaryDownloadHandler, SessionManager, and TracingProvider are specialized components for:
- BinaryDownloadHandler: Streaming binary file downloads (relevant to oundry-file or oundry-code-repository skills with download operations)
- SessionManager: AIP Agents session persistence (relevant to oundry-aip-agents skill)
- TracingProvider: W3C trace context propagation (optional observability enhancement)

None of these are used by the foundry-datasets CLI, which operates entirely on metadata and tabular data via the Foundry Datasets API v2. DEV-STORY-004 components can be deferred until a skill namespace actually requires them.

### Recommendation

**Unblock DEVOPS-004** with the following condition: The _foundry_cli_common.py assembled for deployment shall include only the components actually imported by the datasets CLI (the seven listed above). Any SAD-001 template references to AuthProvider or PaginationHelper are forward-looking and may be omitted from the initial datasets skill deployment.

### Architecture Rationale

This aligns with the SAD-001 principle of "Minimal Surface Area" — each skill ships only the components it requires. The datasets skill is a valid first deployment target with the current common module state. Future skills may pull in additional components (e.g., BinaryDownloadHandler when a file-download skill is deployed).
