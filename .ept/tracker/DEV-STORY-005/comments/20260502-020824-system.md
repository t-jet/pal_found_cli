## Technical Scope Definition

**Objective:** Implement the `foundry-datasets` skill package exposing all operations from the `datasets` namespace of the foundry-platform-python SDK v2 as a Claude Code skill.

### Deliverables

1. **SKILL.md** at `.claude/skills/foundry-datasets/SKILL.md`
   - Frontmatter with skill metadata (name, description, user-invocable: true, tools: [bash], applyTo: ["**"])
   - Tool documentation for all operations organized by resource (branch, dataset, file, transaction, view)
   - Usage examples for each operation showing CLI invocation patterns
   - Error handling guidance and exit code references

2. **CLI Entry Point** at `.claude/skills/foundry-datasets/scripts/foundry_datasets_cli.py`
   - argparse-based CLI with subcommands for each resource type
   - Integration with `_foundry_cli_common.py` (ConfigLoader, AuthProvider, AsyncClientFactory, AccessControlGuard, RetryHandler, OutputFormatter, ErrorSerializer, PaginationHelper, LogSetup)
   - Async main function using `asyncio.run()`
   - Exit code taxonomy per ADR-001

3. **Common Module Copy** at `.claude/skills/foundry-datasets/scripts/_foundry_cli_common.py`
   - Copy from master implementation in DEV-STORY-001 through DEV-STORY-004
   - No modifications required (single source of truth principle)

### Operations Scope

According to the canonical-env-var-reference, the `datasets` namespace contains **33 operations** across 5 resource types:

- **Branch** (5 operations): create, delete, get, list, transactions
- **Dataset** (11 operations): create, get, get_health_check_reports, get_health_checks, get_schedules, get_schema, get_schema_batch, jobs, put_schema, read_table, transactions
- **File** (5 operations): content, delete, get, list, upload
- **Transaction** (6 operations): abort, build, commit, create, get, job
- **View** (6 operations): add_backing_datasets, add_primary_key, create, get, remove_backing_datasets, replace_backing_datasets

**Note:** The ticket title states "26 operations" but the canonical reference shows 33. This discrepancy should be clarified—it may indicate that 7 operations were added post-roadmap, or that some operations are excluded from the initial implementation scope.

### Access Control Integration

The skill must integrate with the 8-step precedence model (SRS §4.2):
1. Global `FOUNDRY_AGENTIC_CLI_ENABLED` check
2. Namespace `FOUNDRY_AGENTIC_CLI_DATASETS_ENABLED` check
3. Operation `FOUNDRY_AGENTIC_CLI_DATASETS_{RESOURCE}_{OP}_ENABLED` check
4. Global `FOUNDRY_AGENTIC_CLI_READONLY` enforcement
5. Namespace `FOUNDRY_AGENTIC_CLI_DATASETS_READONLY` enforcement
6. Operation `FOUNDRY_AGENTIC_CLI_DATASETS_{RESOURCE}_{OP}_READONLY` override
7. Global `FOUNDRY_AGENTIC_CLI_METADATA_ONLY` enforcement
8. Metadata allow-list filtering for applicable operations

### Output Formatting

Support three modes per ADR-004:
- **JSON** (default for single objects and heterogeneous arrays)
- **TOON** (auto-selected for uniform arrays with ≥2 rows)
- **Auto** (algorithm-driven selection)

### Error Handling

All errors must follow ADR-001 exit code taxonomy:
- 0: Success
- 1: General CLI error
- 2: Invalid arguments
- 3: Configuration error
- 4: SDK API error
- 5: Unexpected exception
- 6: Authentication failure
- 7: Network/timeout error
- 8: Access control blocked
- 9: Missing required configuration
