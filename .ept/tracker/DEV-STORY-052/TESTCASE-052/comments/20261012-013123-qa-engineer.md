### Test cases (Given/When/Then)
**TC-052-01 inventory one-to-one (AC-D-013-08).** Given the 15 frozen keys, when record headings are enumerated in references/01-stream.md and 02-subscriber.md, then every key has exactly one record and no extra or duplicate record exists.
**TC-052-02 record completeness sample (AC-D-013-02..05).** Given dataset.create, stream.create, stream.publish_record, stream.publish_binary_record, stream.get_records, stream.get_end_offsets, stream.reset, subscriber.create, subscriber.read_records and subscriber.commit_offsets, when each is read, then resource, effect and side effect, input meaning, result and failure interpretation and a coherent example are correct against the installed CLI.
**TC-052-03 offline copied-folder representative run (AC-D-013-06,07).** Given the copied folder with no network, when a novice agent follows one example per client with mock or recorded output, then it chooses valid inputs, interprets the result and next operation, and every required local link resolves.
**TC-052-04 install prerequisite (BR-012-09).** Given pal-found-streams/SKILL.md, when the install block is read, then it names pal_found_cli and gives conda `-c t-jet`, pip and uv commands.
**TC-052-05 300-line leaf limit (SA-DES-012).** Given every markdown part, when line counts are checked, then each part is at most 300 lines.
**TC-052-06 offset and read semantics (AC-D-013-04,05,09).** Given stream.get_end_offsets, stream.get_records, subscriber.get_read_position, subscriber.read_records, subscriber.commit_offsets and subscriber.reset_offsets, when the records are read, then the meaning of an offset and a read position, the effect of committing versus resetting offsets, the empty-record interpretation and the batch response pattern are stated.
**TC-052-07 long-running read timeout (AC-D-013-05,09).** Given stream.read_records and subscriber.read_records, when the records are read, then the longer streams timeout default (about 120 s, FOUNDRY_AGENTIC_CLI_STREAMS_TIMEOUT_S) and the way to avoid a false timeout on a normal read are stated.
**TC-052-NEG-01 missing or duplicate record.** Given a key with no heading or two headings, when the inventory check runs, then it fails naming the key.
**TC-052-NEG-02 unsupported call.** Given an operation not in the register, when the skill is read, then it is not presented as callable.
**TC-052-NEG-03 stale example.** Given an example selecting a different resource.operation than its heading, when parsed, then it fails.
**TC-052-NEG-04 unresolved link.** Given a relative link that escapes the folder or targets a missing file, when resolved, then it fails.

15/15 keys with exactly one record; zero duplicates or extras; completeness sample passes; zero unresolved local links; install block present; every part at most 300 lines; offset and timeout semantics documented.
