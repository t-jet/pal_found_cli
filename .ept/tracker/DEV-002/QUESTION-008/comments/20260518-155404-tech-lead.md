## Answer: ADR-001 is authoritative — DEV-002 AC2 must conform

**Decision: DEV-002 AC2 (ErrorSerializer) shall use the exit code taxonomy as defined in ADR-001.**

### Rationale

ADR-001 is an Accepted Architecture Decision Record (dated 2026-04-13, decider: Solution Architect). It is the authoritative source for exit code taxonomy across the entire project. DEV-002 acceptance criteria were drafted independently and contain mappings that conflict with the approved ADR.

### Corrected Exit Code Mapping (per ADR-001)

The ErrorSerializer in DEV-002 AC2 must map exceptions to exit codes as follows:

| Code | Exception Name | Conditions (authoritative) |
|---|---|---|
| 0 | Success | Operation completed without error |
| 1 | UserInputError | Invalid CLI arguments, validation failure, missing required parameter |
| 2 | AuthenticationError | Missing or invalid `FOUNDRY_TOKEN` / `FOUNDRY_HOSTNAME`; SDK auth failure |
| 3 | PermissionDeniedError | API returns 403 / `PermissionDeniedError` from SDK |
| 4 | NotFoundError | API returns 404 / resource does not exist |
| 5 | TimeoutError | `asyncio.wait_for()` timeout exceeded; `SIGINT`/`SIGTERM` received |
| 6 | ServerError | API returns 5xx (excluding 503 which is retried); SDK internal error |
| 7 | RateLimitExhausted | HTTP 429 received and maximum retry attempts exhausted |
| 8 | AccessControlError | Operation blocked by CLI access control policy (enabled/readonly/metadata-only) |
| 9 | ConfigurationError | Missing required env var or malformed configuration |

### Corrective Action Required

DEV-002 AC2 must be updated to replace its exit code mapping with the ADR-001 taxonomy above. The following codes need correction:

- **Code 3:** Change `ValidationError` → `PermissionDeniedError`
- **Code 5:** Change `RateLimitError` → `TimeoutError`
- **Code 6:** Change `TimeoutError` → `ServerError`
- **Code 7:** Change `ConflictError` → `RateLimitExhausted`
- **Code 8:** Change `PermissionError` → `AccessControlError`
- **Code 9:** Change `NetworkError` → `ConfigurationError`

Additionally, code 1 should be `UserInputError` (not "General error") and code 2 should be `AuthenticationError` (not `AuthError`).
