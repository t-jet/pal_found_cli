### Documentation Review Summary

Reviewed the following ADRs and related documentation:

1. **ADR-001 (Exit Code Taxonomy) — CRITICAL DISCREPANCY FOUND**
   - ADR-001 maps codes 1-9 as: UserInputError(1), AuthenticationError(2), PermissionDeniedError(3), NotFoundError(4), TimeoutError(5), ServerError(6), RateLimitExhausted(7), AccessControlError(8), ConfigurationError(9)
   - DEV-002 AC2 implements: GeneralError(1), AuthFailure(2), ValidationError(3), ResourceNotFound(4), RateLimited(5), Timeout(6), Conflict(7), PermissionDenied(8), NetworkError(9)
   - **6 of 9 codes mismatch** (codes 3, 5, 6, 7, 8, 9 are wrong). This is a showstopper.
   - Action: QUESTION-008 created, addressed to tech-lead/architect for resolution.

2. **ADR-004 (Format Auto-Selection Algorithm)**
   - OutputFormatter (AC3) must implement the auto-selection algorithm from ADR-004.
   - Key rule: TOON only when data is a list AND all items share identical field sets.
   - All other cases (single object, empty list, mixed types, error envelopes) → JSON.
   - Implementation plan in AC3 is consistent with ADR-004 requirements. No action needed.

3. **ADR-005 (Structured Log Format)**
   - LogSetup (AC4) must emit NDJSON on stderr with required fields: ts, level, logger, msg.
   - Optional context fields: op, call_id, attempt, delay_ms, etc.
   - Log level control via FOUNDRY_AGENTIC_CLI_LOG_LEVEL (default: WARNING).
   - Metadata separator: # ---metadata-start---
   - Implementation plan in AC4 is consistent with ADR-005. No action needed.

4. **ADR-002 (Per-Call Timeout Defaults)**
   - Relevant to RetryHandler (AC1): timeout defaults (30s standard, 120s for streams) don't directly affect retry logic but the RetryHandler should respect the timeout context.
   - Implementation plan references retries on rate limiting (429) which aligns with ADR-005 log example. No conflict.

5. **DESIGN-001 (Technical Design)**
   - Closed status. Confirms design is complete. Implementation plan in DEV-002 covers all 4 ACs.
