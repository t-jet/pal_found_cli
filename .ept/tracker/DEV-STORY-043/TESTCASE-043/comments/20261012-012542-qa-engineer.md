### Test cases (Given/When/Then)
**TC-043-01 inventory one-to-one (AC-D-013-08).** Given the 28 governance keys and 2 audit keys, when record headings are enumerated in references/03-governance.md, references/04-governance-access.md and the audit skill, then every key has exactly one record and no extra or duplicate record exists.
**TC-043-02 record completeness sample (AC-D-013-02..05).** Given one record per client, for example marking.create, organization.create, organization_role_assignment.add, marking_member.add, cbac_marking_restrictions.get, host.list and audit log_file.content, when each is read, then resource, effect and side effect, input meaning, result and failure interpretation and a coherent example are correct against the installed CLI.
**TC-043-03 offline copied-folder representative run (AC-D-013-06,07).** Given both copied folders with no network, when a novice agent follows one example per namespace with mock or recorded output, then it chooses valid inputs, interprets the result and next operation, and every required local link resolves.
**TC-043-04 install prerequisite (BR-012-09).** Given the Admin and Audit SKILL.md files, when the install blocks are read, then each names pal_found_cli and gives conda `-c t-jet`, pip and uv commands.
**TC-043-05 300-line leaf limit (SA-DES-012).** Given every markdown part of both folders, when line counts are checked, then each part is at most 300 lines.
**TC-043-06 audit log download and paging (AC-D-013-04,09).** Given log_file.list and log_file.content, when a short page with a token and a bounded streamed download are read, then the exact-page paging limit, the bounded download limit and the next step are documented, and a short page is not read as end of data.
**TC-043-07 cross-part navigation (AC-D-013-07).** Given the Admin SKILL.md navigation owned by the identity story, when its links to the governance part and to the Audit skill are resolved, then both links resolve within their folders and no part escapes its skill folder.
**TC-043-NEG-01 missing or duplicate record.** Given a key with no heading or two headings, when the inventory check runs, then it fails naming the key.
**TC-043-NEG-02 unsupported call.** Given an operation not in the register, when the skill is read, then it is not presented as callable.
**TC-043-NEG-03 stale example.** Given an example selecting a different resource.operation than its heading, when parsed, then it fails.
**TC-043-NEG-04 unresolved link.** Given a relative link that escapes the folder or targets a missing file, when resolved, then it fails.
