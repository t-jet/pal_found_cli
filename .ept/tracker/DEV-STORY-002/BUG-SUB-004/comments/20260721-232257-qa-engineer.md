### Reproduction executed (TC2.R1)

Component under test: `src/foundry_cli/common/error_serializer.py`, method `ErrorSerializer.serialize()`.
Reproduction command (Windows PowerShell, PYTHONPATH=src):

```powershell
python -c "from foundry_cli.common.log_setup import LogSetup; from foundry_cli.common.error_serializer import ErrorSerializer; from foundry_cli.common.access_control_guard import AccessControlError; LogSetup.configure(log_level='ERROR'); ser = ErrorSerializer(call_id='repro-bug-sub-004-tc2r1'); ser.serialize(AccessControlError('Access control policy denied: datasets.dataset.create blocked at step 3 (READONLY)', step=3))" 1>stdout_repro_20260721.json 2>stderr_repro_20260721.ndjson
```

### Expected behavior (per ADR-001)

- `exit_code = 8`
- `exit_code_name = "AccessControlError"`

### Actual behavior observed (DEFECT CONFIRMED)

stdout envelope:

```json
{"error": true, "exit_code": 1, "exit_code_name": "UserInputError", "message": "Access control policy denied: datasets.dataset.create blocked at step 3 (READONLY)", "exception_type": "AccessControlError", "traceback": "foundry_cli.common.access_control_guard.AccessControlError: ...", "call_id": "repro-bug-sub-004-tc2r1"}
```

- `exception_type` correctly identifies `AccessControlError`, but `exit_code` is **1 (UserInputError)** instead of the required **8 (AccessControlError)**.

### Application log captured (ADR-005 NDJSON on stderr)

stderr log line (single NDJSON record):

```json
{"ts": "2026-07-21T20:19:05.153980+00:00", "level": "ERROR", "logger": "foundry_cli.common.error_serializer", "msg": "Serialized AccessControlError to exit code 1 (UserInputError): Access control policy denied: datasets.dataset.create blocked at step 3 (READONLY)", "call_id": "repro-bug-sub-004-tc2r1"}
```

ADRs satisfied:
- ADR-005: single-line NDJSON on stderr, required fields `ts/level/logger/msg` present, optional `call_id` present, ISO 8601 UTC timestamp.
- ADR-001 violation: exit code taxonomy mismatch — `AccessControlError` must map to `8`, not default to `1`.

### Root cause (for python-developer)

`_EXCEPTION_TO_EXIT_CODE` in `_register_sdk_exceptions()` registers legacy `_SDK*Error` placeholders and SDK `PalantirRPCException` subclasses, but does NOT register `foundry_cli.common.access_control_guard.AccessControlError`. HTTP status classification does not apply (AccessControlError carries no HTTP status), so `serialize()` falls through to the default `EXIT_USER_INPUT` (1). The `EXIT_ACCESS_CONTROL = 8` constant exists but is never selected.
