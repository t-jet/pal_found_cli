# Architect Decision — QUESTION-011

## Decision

**Option (a): Update the implementation to emit the SRS FR-ERR-2 envelope (nested `error` object with `type`, `message`, `http_status`, `details`, `attempt`, `operation`, `call_id`).** Reject option (b) and (c).

Additionally, **augment the AC schema** with `exit_code` and `exit_code_name` (currently only in the implementation) so that ADR-001's exit-code taxonomy remains programmatically accessible downstream. This is option-(a)+reconciliation, not option (c).

## Rationale

1. **AC/SRS is the contract.** FR-ERR-2 + the JSON schema block (SRS lines 251-264) define the authoritative envelope: a **nested** `{ "error": { ... } }` object carrying `type`, `message`, `http_status` (optional), `details` (optional), `attempt`, `operation`, `call_id`. ADR-001 §Decision confirms "All errors also produce a JSON object on stdout using the error schema defined in FR-ERR-2." The implementation's flat `{ "error": true, ... }` envelope is a non-conformant invention.
2. **Downstream consumers depend on the documented shape.** Per ADR-001 Rationale, agent callers and orchestrators parse stdout JSON to choose recovery strategies. A flat schema with `error: true` and no `attempt`/`operation` makes retry-aware orchestration impossible (the agent cannot tell if this was the 1st or Nth attempt, nor which operation failed).
3. **Option (b) (drop fields from AC) breaks FR-ERR-2**, which is sourced from Q&A R1: A4.3 — a customer-confirmed requirement. We cannot silently delete sourced requirements; that needs Product Owner approval and an SRS amendment. Not justified here.
4. **Option (c) (v2 schema with migration path) is over-engineering** for v1 — there are no v1 consumers to migrate from. The current flat envelope was never the contract; aligning to the AC is the migration.
5. **Two-way reconciliation is required** because the implementation added one valuable field (`exit_code`/`exit_code_name`) that the AC schema omits but ADR-001 implies ("exit code is the primary diagnostic channel"). Promoting these into the AC closes the loop without weakening the contract.

## Canonical Envelope Schema (target — implementer to apply)

```json
{
  "error": {
    "type": "AuthenticationError",
    "message": "string",
    "exit_code": 2,
    "exit_code_name": "AuthenticationError",
    "http_status": 401,
    "details": {},
    "attempt": 1,
    "operation": "datasets.dataset.get",
    "call_id": "uuid",
    "exception_type": "AuthenticationError",
    "traceback": "string (suppressed when FOUNDRY_INCLUDE_TRACEBACK=false)"
  }
}
```

### Field Semantics

| Field | Type | Required | Source | Notes |
|---|---|---|---|---|
| `error` | object | yes | FR-ERR-2 | **Nested** wrapper (not boolean) |
| `type` | string | yes | FR-ERR-2 | Logical error class — same as `exit_code_name` for SDK-mapped errors; may differ for unclassified (`"UnknownError"`) |
| `message` | string | yes | FR-ERR-2 | `str(exception)` |
| `exit_code` | int | yes | ADR-001 | 0-9 taxonomy |
| `exit_code_name` | string | yes | ADR-001 | Human-readable name |
| `http_status` | int | optional | FR-ERR-2 | Omit key entirely when no HTTP context |
| `details` | object | optional | FR-ERR-2 | SDK-provided structured details (e.g. validation field errors); omit when empty |
| `attempt` | int | yes | FR-ERR-2 | 1-based retry attempt count (1 = first try; non-retryable errors still report 1) |
| `operation` | string | yes | FR-ERR-2 | SDK path, e.g. `datasets.dataset.get`; `"unknown"` if not in an operation context |
| `call_id` | string | yes | FR-ERR-2 | UUID per CLI invocation |
| `exception_type` | string | yes | impl | Python exception class name (debugging aid; keep) |
| `traceback` | string | optional | impl | Empty string when suppressed |

## Sub-decisions for the implementer

- **`attempt` plumbing:** ErrorSerializer needs the current attempt count. Two options:
  - (i) Pass `attempt` and `operation` into `serialize()` as new keyword args (`attempt: int = 1`, `operation: str = "unknown"`).
  - (ii) Accept a `RetryHandler`-aware context object.
  - **Prefer (i)** — minimal, explicit, testable. The CLI entrypoint that wraps the SDK call knows both values.
- **`details` extraction:** If the SDK exception exposes a structured `body`/`parameters` attribute, copy it into `details`; otherwise omit the key (do NOT emit `"details": {}`).
- **`type` vs `exit_code_name`:** For SDK-mapped exceptions these coincide. For unclassified exceptions, `type = "UnknownError"` and `exit_code_name = "UnknownError"`. Keep both fields — they may diverge in future (e.g. typed-but-unmapped SDK exceptions).
- **`create_error_envelope()` static method** must be updated to the new nested shape with the new kwargs.
