### 2. Technical Scope Analysis

#### Component 1: RetryHandler

**Purpose:** Exponential backoff retry with jitter for transient failures (HTTP 429, 503).

**Key Design Decisions:**
- Wraps SDK async calls in `asyncio.wait_for()` with configurable timeout from `FOUNDRY_AGENTIC_CLI_TIMEOUT_S` (default: 30s)
- Exponential backoff formula: `delay_ms = initial_delay * (multiplier ^ attempt) + random_jitter(±10%)`
- Configurable via 4 env vars: `FOUNDRY_AGENTIC_CLI_RETRY_INITIAL_DELAY_MS` (500), `FOUNDRY_AGENTIC_CLI_RETRY_MAX_DELAY_MS` (30000 per canonical ref — **NOTE: ticket says 8000, canonical ref says 30000**), `FOUNDRY_AGENTIC_CLI_RETRY_MULTIPLIER` (2.0), `FOUNDRY_AGENTIC_CLI_RETRY_MAX_ATTEMPTS` (4)
- Logs retry attempts to stderr as structured JSON per ADR-005

**SDK Exceptions to Handle:**
- `RateLimitError` (HTTP 429) — retry candidate
- `ServiceUnavailable` (HTTP 503) — retry candidate
- `PalantirQoSException` base — check `retry_hint` via `QoSRetryHint.from_headers()`

**Interfaces:**
- Constructor: `RetryHandler(cfg: ConfigLoader, client: AsyncFoundryClient)`
- Method: `async def call(self, coro_factory: Callable, operation: str, **kwargs) -> Any`
- Returns structured error on timeout (exit code 5) or max retries exhausted (exit code 7)

#### Component 2: ErrorSerializer

**Purpose:** Maps SDK exceptions to structured JSON error envelopes and typed exit codes.

**Exception → Exit Code Mapping Table:**

| SDK Exception | Exit Code | Error Type Name |
|---|---|---|
| `BadRequestError` (400) | 1 | UserInputError |
| `UnprocessableEntityError` (422) | 1 | UserInputError |
| `NotAuthenticated` | 2 | AuthenticationError |
| `UnauthorizedError` (401) | 2 | AuthenticationError |
| `PermissionDeniedError` (403) | 3 | PermissionDeniedError |
| `NotFoundError` (404) or `ApiNotFoundError` | 4 | NotFoundError |
| `TimeoutError` (SDK) / `asyncio.TimeoutError` / `KeyboardInterrupt` | 5 | TimeoutError |
| `InternalServerError` (5xx) | 6 | ServerError |
| `RateLimitError` (429, after retries exhausted) | 7 | RateLimitExhausted |
| Access control block | 8 | AccessControlError |
| `EnvironmentNotConfigured` | 9 | ConfigurationError |
| `PalantirException` (base, catch-all) | 1 | UserInputError |
| `SDKInternalError` | 6 | ServerError |
| `ConnectionError` / `ProxyError` | 6 | ServerError |
| Other Python exceptions | 1 | UserInputError |

**Error Schema (stdout JSON):**
{
  "error": {
    "type": "string",
    "message": "string",
    "http_status": "int|null",
    "details": "string|null",
    "attempt": "int|null",
    "operation": "string|null",
    "call_id": "UUID string"
  }
}

**Interfaces:**
- `ErrorSerializer.emit(exc: Exception, operation: str = None, attempt: int = None, call_id: str = None) -> None`
- `ErrorSerializer.exit_code(exc: Exception) -> int`

#### Component 3: OutputFormatter

**Purpose:** Format auto-selection and rendering (JSON/TOON).

**Auto-Selection Algorithm (from ADR-004):**
7-step evaluation: explicit format → error envelope → non-list → empty list → field set extraction → non-dict items → uniform field set check.

**Interfaces:**
- Constructor: `OutputFormatter(format_setting: str = "auto")`
- Method: `def emit(self, data: Any, is_binary_download: bool = False) -> None` — writes to stdout
- Method: `def emit_metadata(self, metadata: dict) -> None` — writes to stderr with separator

**Dependencies:**
- `toon-python >=0.9,<1.0` library — wrapped in try/except with JSON fallback
- `json` stdlib module

#### Component 4: LogSetup

**Purpose:** Configure Python `logging` with NDJSON formatter directed to stderr.

**Design:**
- Custom `logging.Formatter` subclass producing JSON records
- Required fields: `ts`, `level`, `logger`, `msg`
- Optional context fields: `op`, `call_id`, `attempt`, `delay_ms`, `access_decision`, `http_status`
- ISO 8601 UTC timestamps
- Log level from `FOUNDRY_AGENTIC_CLI_LOG_LEVEL` (default: WARNING)
- Metadata separator: `# ---metadata-start---` on stderr before metadata JSON

**Interfaces:**
- `def configure(log_level: str = "WARNING") -> None`

### 4. Constraints

- Must be compatible with Python 3.11+ type hints
- All components in single `_foundry_cli_common.py` file
- No network calls on import
- Logging must not interfere with stdout/stderr CLI contract
- TOON library wrapped in try/except; fallback to JSON on failure
- SIGINT/SIGTERM must cancel retry operations gracefully
- All errors as JSON on stdout regardless of `--format` setting

### 5. Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `toon-python` API instability | Medium | Medium | Version pin >=0.9,<1.0; JSON fallback on any TOON failure |
| SDK exception hierarchy changes | Low | High | Exception mapping table with catch-all fallback to exit code 1 |
| Retry thundering herd | Medium | Medium | ±10% random jitter on all delays |
| Stderr log + metadata collision | Low | High | `# ---metadata-start---` separator per ADR-005 |

### 6. Questions

**Q1 — Retry max delay discrepancy:** The ticket acceptance criteria state `FOUNDRY_AGENTIC_CLI_RETRY_MAX_DELAY_MS` default is 8000ms, but the canonical env var reference states 30000ms. **Resolution needed:** Confirm which value is authoritative. Per ADR-002 and exponential backoff (500 × 2^n), 8000ms makes more sense (attempt 4: 500 × 8 = 4000 + jitter), so I will use 8000ms unless corrected.
