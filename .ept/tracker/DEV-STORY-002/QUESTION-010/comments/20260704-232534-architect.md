# Architect Decision — QUESTION-010

## Decision

**Option (b): Update the implementation to use the canonical `FOUNDRY_AGENTIC_CLI_RETRY_*` names; deprecate the current `FOUNDRY_*` retry names.**

## Rationale

1. **Canonical reference is authoritative.** `canonical-env-var-reference.md` (ENV-REF-001) defines the project-wide convention `FOUNDRY_AGENTIC_CLI_{KEY}` and lists the four retry variables explicitly as `FOUNDRY_AGENTIC_CLI_RETRY_INITIAL_DELAY_MS`, `_MAX_DELAY_MS`, `_MULTIPLIER`, `_MAX_ATTEMPTS`. ADR-002 confirms the parallel pattern (`FOUNDRY_AGENTIC_CLI_TIMEOUT_S`). Every other namespace follows the same prefix.
2. **Naming alignment is cheap now, expensive later.** RetryHandler (`retry.py`) is new code in DEV-STORY-002; no external consumers depend on the current names. Aligning now avoids a permanent exception in the naming scheme and prevents future cross-skill inconsistency (355+ operation vars already follow the canonical pattern).
3. **Option (a) (accept `FOUNDRY_*`) would create a documented exception** that contradicts the ENV-REF and SRS Table 5.3, requiring updates to ADR-002, SRS, ENV-REF, and the .env.example, and would still leave the retry subsystem visually inconsistent with every other control var.
4. **Option (c) (support both with deprecation) is rejected** for v1 — it doubles the test matrix and the `.env.example` surface for no user benefit at this stage. A deprecation alias can be added in a follow-up if backward compatibility becomes a concern post-release.

## Required Variable Mapping (implementer to apply)

| Current (impl) | Canonical (target) |
|---|---|
| `FOUNDRY_MAX_RETRIES` | `FOUNDRY_AGENTIC_CLI_RETRY_MAX_ATTEMPTS` |
| `FOUNDRY_RETRY_BASE_DELAY` | `FOUNDRY_AGENTIC_CLI_RETRY_INITIAL_DELAY_MS` (note: **milliseconds**, see below) |
| `FOUNDRY_RETRY_MAX_DELAY` | `FOUNDRY_AGENTIC_CLI_RETRY_MAX_DELAY_MS` |
| `FOUNDRY_RETRY_JITTER` | **No canonical equivalent** — see note below |
| *(none)* | `FOUNDRY_AGENTIC_CLI_RETRY_MULTIPLIER` (currently hardcoded `2.0`? expose it) |

## Sub-decisions / Caveats for the implementer (developer/python-developer)

- **Units mismatch:** canonical reference specifies **milliseconds** (`_INITIAL_DELAY_MS` default 500, `_MAX_DELAY_MS` default 30000); the current implementation uses **seconds** (defaults 1.0 and 30.0). The implementer MUST convert the internal units to milliseconds when reading these env vars to match the canonical defaults (500 ms initial, 30000 ms max). Internal arithmetic may stay in seconds after parsing.
- **Jitter:** `FOUNDRY_RETRY_JITTER` has no canonical entry. Keep the feature but rename to `FOUNDRY_AGENTIC_CLI_RETRY_JITTER` (bool, default `true`) and add a one-line entry to ENV-REF-001 Section "Global Configuration Variables" so the doc stays authoritative.
- **Multiplier:** expose `FOUNDRY_AGENTIC_CLI_RETRY_MULTIPLIER` (float, default `2.0`) as a configurable parameter rather than hardcoding, to close the gap with the canonical reference.
