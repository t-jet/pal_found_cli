## Required correction: finite reader pagination

Two published worked examples can continue indefinitely when a server keeps returning a continuation token:

- `.agents/skills/pal-found-dev/references/rest/v2/ontologies/LinkedObject.md:41`: `while True:`. Lines 52-54 assign `page_token = page.next_page_token` and break only for `None`. Affected operation: `v2.ontologies.LinkedObject.list_linked_objects`.
- `.agents/skills/pal-found-dev/references/rest/v2/ontologies/OntologyObject.md:73`: `while True:`. Lines 83-85 have the same continuation-only stop. Affected operation: `v2.ontologies.OntologyObject.list`.

Both loops append results before requesting the next page. Neither has a finite page/item budget, deadline, or repeated-token check. The final membership assertions also lack an explicit incomplete-result outcome when a caller stops early. SA-DES-014 `rest-and-sources.md` section 2.2 requires finite budgets, repeated-token rejection and partial-result reporting. The resource-guide acceptance criteria require finite iteration and bounded recovery.

Independent adversarial probe executes each exact extracted loop AST with SDK-shaped raw response objects. Each response contains one object and `next_page_token='same-token'`. Both loops closed 100 responses, accumulated 100 duplicate keys and attempted request 101. Only the external probe stop prevented further requests. This proves an unbounded reader algorithm; it does not claim that a real tenant server returned repeated tokens. Probe exited 0 with both findings reproduced.

Correction must add explicit finite page/item work bounds and a live request/time budget; reject a repeated continuation token; report an incomplete/partial outcome when any bound stops traversal; and avoid claiming complete enumeration from partial results. Preserve `raw.close()` in `finally`, continue through empty intermediate pages with new tokens, and finish normally when the token is absent. Add focused offline checks that exercise the published worked-example logic for repeated tokens, budget exhaustion, empty intermediate pages and terminal completion. Preserve object identity and existing named-envelope fixtures. Reviewer must re-run these checks before approval.
