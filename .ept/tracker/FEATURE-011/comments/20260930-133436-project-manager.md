Scope assessment from the requirement (Project Owner):

- All 18 namespace skills under pal_found_cli_skills/.agents/skills/pal-found-* contain a scripts/pal_found_*_cli.py launcher.
- 16 are THIN WRAPPERS that only import build_parser/console_main/main from the tool and call console_main(). These add no logic of their own.
- 2 are FULL STANDALONE IMPLEMENTATIONS with their own parser+business logic: pal-found-datasets (pal_found_datasets_cli.py, ~347 lines, own build_parser/main) and pal-found-ontologies (pal_found_ontologies_cli.py, ~214 lines, own build_parser/main). These represent 'separate command implementations' the owner wants moved into the tool.

Requirement implications:
1. Skills should contain ONLY documentation (SKILL.md) that invokes the packaged pal-found-* CLI commands. No python scripts in skills.
2. Any additional python code / separate command implementations must live in the tool itself (pal_found_cli_tool).
3. Skills must not require python knowledge by the user.

Open design questions for BA/SA:
- Are the pal-found-datasets and pal-found-ontologies full implementation scripts duplicate/divergent from the tool's own pal_found_cli datasets/ontologies modules? If so, migrate to the tool and make skills doc-only.
- Should all 18 thin-wrapper launchers be removed from the skills repo, with SKILL.md referencing pal-found-* commands only?
- Does the tool expose all needed pal-found-* commands so doc-only skills can function without python?
- Impact on existing TESTEXEC/DEVOPS evidence and the delivered skills repo.
