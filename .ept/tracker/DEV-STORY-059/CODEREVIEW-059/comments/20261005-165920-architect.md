My earlier approval treated the 10,000-object List Objects limit as universal because the generic Paging page presents it that way. The operation-specific v2 List Objects page says the limit applies only to Object Storage V1 backed objects; Object Storage V2 backed objects have no such limit: https://www.palantir.com/docs/foundry/api/v2/ontologies-v2-resources/ontology-objects/list-objects.

In .agents/skills/pal-found-dev/references/rest-api.md:39, the sentence 'List Objects returns at most 10,000 objects' needs this qualifier. Lines 51 and 65-73 describe and enforce the 10,000 cap as the endpoint's limit even for OSv2, telling users to narrow a query unnecessarily. Keep an optional sample work cap if desired, but label it client-chosen and separate from server's OSv1 limit. The existing ontology-object guide states this distinction correctly at .agents/skills/pal-found-ontologies/references/ontology-object.md:40.
