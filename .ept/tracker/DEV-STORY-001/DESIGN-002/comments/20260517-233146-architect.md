## Design Plan for DEV-STORY-001

### Scope
This design review covers three foundational components:
1. **ConfigLoader** — .env file loading with git-root search path (ADR-006)
2. **AuthProvider** — UserTokenAuth wrapper with credential validation
3. **AsyncClientFactory** — Stateless AsyncFoundryClient creation with attribution headers

### Design Decisions
1. ConfigLoader uses python-dotenv load_dotenv(override=False); shell env vars take precedence over .env values
2. Git root detection via pathlib ancestor walk with depth limit of 20 levels
3. AuthProvider constructs UserTokenAuth from resolved token string — no credential logging
4. AsyncClientFactory creates new instance per invocation; stateless pattern
5. Attribution headers injected only when ENABLE_ATTRIBUTION=true

### Critical Thinking Summary
- ConfigLoader is the first component invoked in the chain; all other components depend on it
- AuthProvider wraps foundry-auth's UserTokenAuth — minimal abstraction layer
- AsyncClientFactory is intentionally stateless per invocation (no caching)
- Security: credentials never logged or written to stdout — enforced in tests
- Error handling follows ADR-001: ConfigurationError (exit code 9), AuthenticationError (exit code 2)

### Risk Assessment
- Low risk: All components are pure Python with well-defined dependencies
- python-dotenv is mature and well-tested
- foundry-auth SDK is the primary external dependency — version pinning recommended
- Attribution header logic is straightforward conditional injection

**Design Status: APPROVED** — Proceed with implementation.
