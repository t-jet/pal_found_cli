## AT-4 Rule-Handler Gap — escalation to Project Workflow Manager

**To:** `workflow-mgr` (Project Workflow Manager — owns workflow-process integrity and health)
**Cc:** `project-owner`

### Symptom
Auto-transition rule **AT-4 `child_blocker_created`** did not fire on DEV-STORY-001 when:
- 2026-07-21 QUESTION-024 (`question` type) was created under DEV-STORY-001, AND
- `Blocks` link LINK-00154 (QUESTION-024 → DEV-STORY-001) was registered, AND
- DEV-STORY-001 was in `Resolved` status (non-terminal).

Per the rule, the parent should auto-transition to `Blocked`.

### Why a forced manual transition is not a valid fix
`tracker_cli.py get workflow transitions dev_story Resolved` returns only terminal exits:
```
-> Closed      [TERMINAL]
-> Canceled    [TERMINAL]
-> Rejected    [TERMINAL]
-> Duplicated  [TERMINAL]
```
`Blocked` is **not** in the transition map for `dev_story` from `Resolved`. Any tooling built strictly on the transition map will refuse the move; forcing it would corrupt the transition table.

### Suspected rule-handler defects
1. **Transition-map gap:** `Blocked` is not reachable from `Resolved` (or any near-terminal status) for `dev_story` — the auto-transition handler has nowhere to land even if the trigger fires.
2. **Trigger firing:** Whether the AT-4 trigger detected the Blocks-link creation under a `Resolved`-status parent is unclear; needs log/trace review.
3. **Generalization:** Same gap likely affects other ticket types when a blocker is created while the parent is in `Resolved`. Worth verifying across all type/status combinations where AT-4 should apply.

### Requested action (workflow-mgr)
- Investigate AT-4 trigger/handler; confirm whether the transition map for `Resolved` (and equivalent near-terminal statuses across types) should permit `Blocked` as a non-terminal escape, **or** whether AT-4 should be re-scoped to "if parent is in a state where Blocked is reachable".
- File the rule-handler correction / workflow-config update in the appropriate channel (workflow SKILL or tracker engine, whichever owns ATs).
- Reply by comment on this ticket (or on a follow-up QUESTION/RFC) with the ruling.
